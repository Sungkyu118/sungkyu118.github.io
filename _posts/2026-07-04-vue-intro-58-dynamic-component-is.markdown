# Vue 입문 58: 동적 컴포넌트와 component :is 사용하기

> 상태에 따라 렌더링할 컴포넌트를 바꾸는 동적 컴포넌트 문법을 배웁니다.

상태에 따라 다른 컴포넌트를 보여주고 싶을 때가 있습니다. 예를 들어 설정 화면에서 프로필 탭을 선택하면 `ProfilePanel`, 보안 탭을 선택하면 `SecurityPanel`, 알림 탭을 선택하면 `NotificationPanel`을 보여주는 식입니다. `v-if`를 여러 개 쓸 수도 있지만, 컴포넌트 종류가 많아지면 템플릿이 길어집니다.

Vue의 동적 컴포넌트는 `<component :is="...">` 문법으로 현재 렌더링할 컴포넌트를 선택합니다. `is`에는 컴포넌트 객체나 등록된 컴포넌트 이름을 넣을 수 있습니다. Composition API에서는 보통 컴포넌트 객체를 매핑해서 사용하면 명확합니다.

동적 컴포넌트는 탭, 위저드 단계, 설정 패널처럼 같은 위치에 서로 다른 컴포넌트를 교체해 보여줄 때 유용합니다. 다만 상태가 바뀔 때 이전 컴포넌트가 사라지고 새 컴포넌트가 만들어질 수 있으므로 내부 상태 유지가 필요한 경우에는 KeepAlive를 함께 고려해야 합니다.

## 이번 글에서 먼저 잡을 관점

이번 구간부터는 Vue를 단순히 한 파일 안에서 쓰는 단계에서 벗어나, 여러 컴포넌트가 함께 동작하는 구조를 다룹니다. 그래서 문법 하나만 보는 것보다 역할과 책임을 같이 보는 것이 중요합니다. 부모 컴포넌트가 무엇을 알고 있어야 하는지, 자식 컴포넌트는 어디까지 책임져야 하는지, 사용자의 행동을 어느 방향으로 전달해야 하는지 계속 질문하면서 읽어보시면 좋습니다.

컴포넌트 설계는 처음부터 완벽하게 나누는 일이 아닙니다. 작은 화면을 만들고, 반복되는 부분이나 책임이 분명한 부분을 발견하고, 그때 적절히 분리하는 과정에 가깝습니다. 이 글의 예제도 정답이라기보다 기준을 잡기 위한 출발점으로 봐주세요. 직접 이름을 바꿔보고, props를 하나 추가해보고, 이벤트 흐름을 바꿔보면 훨씬 오래 기억에 남습니다.

## 작은 실습으로 확인해보기

아래 예제는 선택된 탭에 따라 다른 패널 컴포넌트를 렌더링합니다.

```vue
<script setup>
import { computed, ref } from 'vue'
import ProfilePanel from './ProfilePanel.vue'
import SecurityPanel from './SecurityPanel.vue'
import NotificationPanel from './NotificationPanel.vue'

const currentTab = ref('profile')

const panels = {
  profile: ProfilePanel,
  security: SecurityPanel,
  notification: NotificationPanel
}

const currentPanel = computed(() => panels[currentTab.value])
</script>

<template>
  <button @click="currentTab = 'profile'">프로필</button>
  <button @click="currentTab = 'security'">보안</button>
  <button @click="currentTab = 'notification'">알림</button>

  <component :is="currentPanel" />
</template>
```

## 코드가 움직이는 순서

`currentTab`은 현재 선택된 탭입니다. `panels` 객체는 탭 값과 컴포넌트를 연결합니다. `currentPanel` computed는 현재 탭에 맞는 컴포넌트를 반환합니다. 템플릿의 `<component :is="currentPanel" />`는 그 컴포넌트를 렌더링합니다.

여기서 중요한 것은 코드 줄 수보다 의도입니다. 컴포넌트를 나누면 파일은 늘어나지만, 각 파일이 맡는 역할이 선명해져야 합니다. 부모는 전체 상태와 흐름을 관리하고, 자식은 자신이 맡은 UI 조각을 표현하거나 사용자 행동을 이벤트로 알려주는 식으로 역할을 나누면 디버깅이 훨씬 쉬워집니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 동적 컴포넌트가 undefined가 되면 렌더링이 깨질 수 있습니다. 매핑 객체에 해당 키가 있는지 확인해야 합니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: 컴포넌트를 교체하면 이전 컴포넌트 내부 상태가 사라질 수 있습니다. 상태 유지가 필요하면 KeepAlive를 고려하세요. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: 단순 조건 두세 개라면 v-if가 더 명확할 수 있습니다. 동적 컴포넌트는 종류가 늘어나거나 구조가 반복될 때 효과가 큽니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.

컴포넌트 관련 오류는 한 파일만 봐서는 바로 보이지 않을 때가 많습니다. 부모가 넘기는 prop 이름, 자식이 선언한 prop 이름, 자식이 emit하는 이벤트 이름, 부모가 듣는 이벤트 이름을 한 줄씩 맞춰보는 습관이 필요합니다. 브라우저 콘솔의 Vue warning도 그냥 넘기지 말고, 어떤 컴포넌트에서 발생했는지 확인해보시면 좋습니다.

## 실무에서 생각할 점

동적 컴포넌트는 템플릿을 깔끔하게 만들지만, 어떤 컴포넌트가 렌더링되는지 코드 추적이 한 단계 늘어납니다. 매핑 객체 이름과 탭 값을 명확히 관리하면 유연성과 가독성을 함께 얻을 수 있습니다.

실무에서는 컴포넌트가 "동작한다"보다 "변경에 견딘다"가 더 중요해집니다. 요구사항은 계속 바뀌고, 디자인도 바뀌고, 같은 컴포넌트를 다른 화면에서 쓰고 싶어질 수 있습니다. 그래서 처음부터 모든 것을 일반화하려고 하기보다, 현재 책임을 명확히 하고 나중에 반복이 보일 때 재사용성을 높이는 방향이 안전합니다.
