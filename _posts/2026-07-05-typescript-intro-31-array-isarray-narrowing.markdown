TypeScript를 계속 배우다 보면, 처음에는 단순해 보였던 개념도 실제 코드로 들어가는 순간 갑자기 어렵게 느껴질 수 있습니다. 특히 31~60 구간은 문법을 하나 더 외우는 구간이 아니라, 타입 시스템을 실제 코드에 어떻게 연결할지 감각을 넓혀가는 구간입니다. 그래서 이번 글에서도 정의만 짧게 정리하는 대신, 예제를 많이 보면서 "왜 이 판단이 필요한지", "이 코드를 어떻게 읽어야 하는지", "실수하면 어떤 문제가 생기는지"를 함께 살펴보겠습니다.

배열인지 아닌지에 따라 사용할 수 있는 메서드가 달라지기 때문에, Array.isArray를 활용한 narrowing은 실무에서도 매우 자주 등장합니다. TypeScript는 결국 코드를 더 예측 가능하게 만드는 도구이기 때문에, 문법을 아는 것보다도 그 문법이 어떤 실패를 줄여주는지 이해하는 편이 훨씬 중요합니다. 지금 단계에서는 특히 예제 코드를 그냥 읽고 넘어가지 말고, 값 하나를 바꾸거나 조건을 바꿔보면서 어떤 에러가 나는지 직접 확인해보시면 좋겠습니다.

## 먼저 이해해야 할 핵심 관점

이번 글의 핵심은 narrowing 심화 흐름 안에서 현재 주제가 어떤 역할을 하는지 파악하는 것입니다. 입문자분들이 TypeScript를 배우다가 자주 흔들리는 이유는, 개념을 각각 따로 외우려 하기 때문입니다. 하지만 실제 코드에서는 조건문, 객체 구조, 함수 호출, API 응답, 상태 모델링이 전부 연결되어 움직입니다. 그래서 지금 주제를 볼 때도 "이 개념이 나중에 어떤 종류의 버그를 막아줄까?"라는 질문을 함께 가져가시면 이해가 훨씬 오래갑니다.

narrowing 구간은 if 문만 많이 쓰는 문법이 아니라, 여러 가능성 중 지금 안전하게 사용할 수 있는 값이 무엇인지 판단하는 사고방식을 익히는 구간입니다. 지금 구간은 특히 '편해 보이는 코드'와 '안전한 코드'가 다를 수 있다는 사실을 자주 보여줍니다. 그래서 에러가 났을 때 바로 단언으로 덮는 습관보다는, 왜 그 에러가 났는지 읽고 타입 흐름을 다시 추적하는 연습이 더 중요합니다.

## 기본 예제부터 차근차근 보기

아래 첫 번째 예제는 이번 주제를 가장 작은 형태로 보여줍니다. 처음에는 모든 줄을 외우려 하지 마시고, 값이 어떤 조건을 만족할 때 어떤 타입으로 보이는지, 혹은 객체 구조가 어떤 의도를 담고 있는지만 먼저 살펴보시면 좋습니다.

```ts
function printValue(value: string[] | string) {
  if (Array.isArray(value)) {
    console.log(value.join(', '))
    return
  }

  console.log(value.toUpperCase())
}
```

이 예제는 지금 주제를 아주 압축해서 보여줍니다. TypeScript에서는 이런 작은 선언 하나가 이후 코드 전체의 안전성을 크게 바꾸는 경우가 많습니다. 입문 단계에서는 결과가 당장 같아 보일 수 있지만, 코드가 길어지고 데이터가 복잡해질수록 이런 작은 타입 선언의 차이가 버그 예방으로 이어집니다.

## 한 단계 더 나아간 예제

실제 프로젝트에서는 기본 문법 하나만 단독으로 쓰이는 경우보다, 함수 호출이나 조건문, 여러 속성이 연결된 형태로 등장하는 경우가 많습니다. 그래서 두 번째 예제에서는 지금 개념이 실제 코드 흐름 안에서 어떻게 쓰이는지 조금 더 구체적으로 보겠습니다.

```ts
const values: unknown = ['ts', 'js']

if (Array.isArray(values)) {
  console.log(values.length)
}
```

이 단계에서는 "타입이 맞다"만 보는 것이 아니라, "읽는 사람이 이 코드의 의도를 쉽게 이해할 수 있는가?"도 함께 봐야 합니다. TypeScript는 단순히 빨간 줄을 없애는 도구가 아니라, 협업하는 사람들이 코드를 더 빠르게 읽고 더 자신 있게 수정할 수 있게 도와주는 도구이기 때문입니다.

## 초보자가 자주 만드는 잘못된 예제

이제 일부러 잘못 작성한 코드를 보겠습니다. 이런 예제를 함께 보는 이유는 단순히 틀린 코드를 찾기 위해서가 아니라, TypeScript가 왜 이 코드를 불편하게 느끼는지 이해하기 위해서입니다.

```ts
function printValue(value: string[] | string) {
  console.log(value.join(', '))
}
```

이런 코드는 처음에는 짧고 편해 보일 수 있습니다. 하지만 실제로는 런타임에서만 터지는 문제를 품고 있거나, 이후 코드를 읽는 사람이 잘못된 가정을 하게 만들 가능성이 큽니다. 그래서 지금처럼 작은 예제에서부터 "편한 코드"와 "안전한 코드"를 구분하는 감각을 익혀두는 것이 중요합니다.

## 에러와 유의사항을 자세히 짚어보기

- 첫 번째로, 지금 주제를 눈으로만 이해했다고 생각하면 실제 코드에서는 바로 막힐 수 있습니다. 예제를 복사해서 값이나 분기를 바꿔보며 에러 메시지를 직접 확인해보셔야 감각이 잡힙니다.
- 두 번째로, TypeScript가 막는 이유를 읽지 않고 빨간 줄만 없애려 하면 나중에 더 큰 문제를 만나게 됩니다. 특히 이 구간은 as 단언이나 non-null assertion처럼 편해 보이는 우회로가 자주 등장하기 때문에 더 조심해야 합니다.
- 세 번째로, 지금 배우는 개념은 다음에 배우는 객체 타입 설계나 제네릭과도 이어집니다. 따라서 문법 하나로 고립해서 보기보다, 앞으로 타입 흐름이 어떻게 확장될지 같이 생각하면서 읽는 편이 좋습니다.

## 실무에서는 어떻게 연결될까요?

실무에서는 지금 배우는 패턴이 그대로 API 응답 처리, 상태 관리, 폼 검증, DTO 설계, 유틸 함수 작성으로 이어집니다. 예를 들어 narrowing을 잘 이해하면 외부 데이터 검증이 훨씬 안정적이고, 객체 타입 구조를 잘 설계하면 프론트엔드와 백엔드 사이의 데이터 계약도 훨씬 분명해집니다. 또 제네릭을 이해하면 반복되는 유틸 함수를 타입 안전하게 재사용할 수 있게 됩니다.

그래서 이번 글도 문법 하나를 배웠다고 끝내기보다, "실제 프로젝트에서 이 개념이 어디에 쓰일까?"를 함께 떠올려보시면 좋겠습니다. 그런 연결이 생기면 나중에 Vue, React, Node.js 코드로 넘어갈 때도 TypeScript를 따로 외우는 느낌이 아니라, 자연스럽게 도구처럼 쓰게 됩니다.

## 오늘 내용 정리
