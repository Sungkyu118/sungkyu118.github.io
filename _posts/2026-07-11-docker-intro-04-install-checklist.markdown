Docker를 설치한 뒤 가장 흔하게 나오는 반응은 두 가지입니다. 하나는 "버전이 뜨니까 다 된 것 같아요"이고, 다른 하나는 "분명 설치했는데 명령어가 안 먹어요"입니다. 둘 다 아주 흔한 상황입니다. Docker는 설치 자체보다 설치 직후 점검이 더 중요하다고 느껴질 정도로, 운영체제별 차이와 권한 이슈, 데몬 실행 상태 같은 변수가 자주 등장합니다. 그래서 이번 글에서는 Docker를 처음 설치한 뒤 무엇부터 확인하면 좋은지 순서대로 정리해보겠습니다.

처음부터 너무 많은 것을 한 번에 확인하려고 하면 오히려 더 헷갈릴 수 있습니다. 그래서 지금 단계에서는 "명령어가 존재하는가", "Docker 데몬이 떠 있는가", "이미지 pull과 컨테이너 실행이 가능한가", "권한 문제는 없는가" 정도를 중심으로 차근차근 확인하는 흐름이 좋습니다. 이 순서를 익혀두면 나중에 다른 PC에서 Docker를 다시 설치하거나, 팀원 환경을 같이 봐줄 때도 아주 큰 도움이 됩니다.

## 먼저 이해해야 할 핵심 관점

이번 글의 핵심은 Docker가 단순 실행 파일 하나가 아니라, 백그라운드에서 돌아가는 Docker 데몬과 클라이언트 명령어가 함께 움직이는 구조라는 점을 이해하는 것입니다. 초보자분들이 가장 자주 만나는 에러 중 하나가 `docker: command not found`와 `Cannot connect to the Docker daemon`인데, 이 둘은 비슷해 보여도 완전히 다른 문제입니다. 하나는 명령어 자체를 찾지 못하는 문제이고, 다른 하나는 명령어는 있지만 뒤에서 실제로 컨테이너를 관리해주는 서비스와 연결이 안 되는 문제입니다.

이 차이를 알고 있으면 에러가 나와도 덜 당황하게 됩니다. Docker 실습은 보통 `hello-world`부터 시작하지만, 그 전에 최소한 설치 체크 기준을 한 번 잡아두는 것이 좋습니다. 지금은 단순히 명령어만 따라 치기보다, "이 명령은 무엇을 점검하는 용도인가?"를 같이 붙여서 이해해보시면 좋겠습니다.

## 가장 먼저 확인할 명령어

Docker 설치 직후에는 아래 두 명령어부터 확인하시면 좋습니다.

```bash
docker --version
docker info
```

`docker --version`은 클라이언트 명령어가 정상적으로 잡혀 있는지 확인하는 가장 기본적인 출발점입니다. 이 명령이 아예 안 된다면 PATH 문제, 설치 실패, 셸 재시작 누락 같은 쪽을 먼저 의심해야 합니다. 반면 `docker info`는 훨씬 많은 정보를 보여줍니다. Docker 데몬 상태, 실행 환경, 저장소 드라이버, 컨테이너 수, 이미지 수 같은 정보가 나오기 때문에, 이 명령이 정상적으로 나오는지만 봐도 설치 상태를 꽤 많이 확인할 수 있습니다.

초보자분들이 여기서 자주 하는 실수는 `docker --version`만 성공하면 모든 준비가 끝난 것으로 생각하는 것입니다. 하지만 실제로는 `docker info`까지 정상적으로 나와야 "명령어도 있고, Docker 서비스도 떠 있다"라고 조금 더 안심할 수 있습니다. 그래서 두 명령어는 반드시 짝으로 확인하시는 것이 좋습니다.

## 운영체제별로 조금씩 다른 점

Windows와 macOS에서는 보통 Docker Desktop을 많이 사용합니다. 이 경우 설치 후 앱이 실제로 실행 중인지도 중요합니다. 프로그램이 설치되어 있어도 Docker Desktop이 아직 켜지지 않았거나, 초기화가 끝나지 않았으면 명령어가 기대한 대로 동작하지 않을 수 있습니다. Linux에서는 Docker Engine과 서비스 상태를 직접 다루는 경우가 많아서, 설치 후 서비스가 활성화되어 있는지까지 확인하는 흐름이 자주 필요합니다.

예를 들어 Linux에서는 아래처럼 확인하는 경우가 많습니다.

```bash
systemctl status docker
```

Windows나 macOS에서는 이 명령을 그대로 쓰지는 않지만, 핵심 감각은 같습니다. 즉, Docker는 설치 파일만 있다고 끝나는 것이 아니라 실제로 뒤에서 구동되는 서비스가 준비되어 있어야 합니다. 이 점을 놓치면 `docker info`가 안 뜨는데도 원인을 못 찾고 오래 헤매게 되는 경우가 많습니다.

## 권한 문제는 왜 자주 나오나요?

특히 Linux 환경에서는 권한 문제가 자주 나옵니다. Docker 소켓에 접근할 권한이 없어서 `permission denied` 비슷한 에러가 뜨는 경우가 대표적입니다. 이때 많은 분들이 무조건 `sudo`를 붙이는 습관부터 들이는데, 일단은 왜 이런 에러가 나는지 이해하는 것이 먼저입니다. Docker는 시스템 자원에 접근하는 도구라서 권한이 중요하고, 설치 후 사용자 그룹 설정이 필요한 경우도 있습니다.

Windows나 macOS에서도 권한 문제는 다른 모습으로 나타날 수 있습니다. 예를 들어 회사 PC 정책 때문에 가상화 기능이 막혀 있거나, WSL 연동이 제대로 안 되어 Docker Desktop이 예상대로 동작하지 않는 경우도 있습니다. 그래서 설치 체크를 할 때는 "버전이 뜨는가"만 볼 것이 아니라, 실제로 컨테이너 실행까지 가능한가를 꼭 끝까지 확인해야 합니다.

## 실제로 잘 설치됐는지 확인하는 가장 좋은 기준

결국 Docker가 제대로 설치되었는지 확인하는 가장 좋은 기준은, 아주 작은 이미지를 가져와서 실행해보는 것입니다. 그 역할을 가장 많이 하는 것이 다음 글에서 다룰 `hello-world`입니다. 다만 지금 단계에서는 아직 실행 원리보다 설치 체크에 집중하고 있으니, 최소한 아래 질문에 답할 수 있으면 좋습니다.

- `docker --version`이 되는가
- `docker info`가 되는가
- Docker Desktop 또는 Docker 서비스가 실제로 떠 있는가
- 권한 에러 없이 명령을 실행할 수 있는가

이 네 가지가 확인되면, 입문 실습을 시작할 기본 준비는 거의 끝났다고 보셔도 됩니다.

## 초보자가 자주 막히는 지점

가장 흔한 문제는 셸을 다시 열지 않아서 PATH 반영이 안 되는 경우입니다. 설치 후 바로 기존 터미널에서 명령을 실행했다가 `docker`를 못 찾는 경우가 꽤 많습니다. 또 Docker Desktop을 설치했지만 아직 앱이 백그라운드에서 완전히 초기화되지 않은 상태에서 명령을 넣었다가 연결 실패를 만나는 경우도 자주 있습니다. 이럴 때는 괜히 복잡한 설정부터 건드리기보다, 아주 기본적인 상태 체크부터 다시 보는 것이 좋습니다.

또 하나 자주 나오는 문제는 회사나 학교 PC에서 가상화 관련 기능이 꺼져 있는 경우입니다. 이때는 Docker Desktop이 겉보기엔 설치됐어도 실제 실행에 실패할 수 있습니다. 그래서 실습이 시작도 안 되는 상황이라면, Docker 자체의 명령어보다 먼저 시스템 요구사항과 실행 환경을 다시 확인하는 편이 훨씬 빠릅니다.

## 오늘 내용 정리

이번 글에서는 Docker 설치 후 가장 먼저 확인해야 할 것들을 중심으로, `docker --version`, `docker info`, Docker 데몬 상태, 권한 문제, 운영체제별 차이를 차근차근 정리해보았습니다. 지금 단계에서는 무리해서 복잡한 명령을 많이 실행하기보다, 기본 점검 흐름을 한 번 손에 익혀두는 것이 더 중요합니다. 이 흐름만 익혀도 이후 실습에서 막혔을 때 훨씬 빠르게 원인을 좁힐 수 있습니다.

가능하시면 지금은 직접 본인 환경에서 `docker --version`과 `docker info`를 실행해보시고, 결과가 각각 어떤 의미인지 한 번 연결해서 생각해보시면 좋겠습니다. 그렇게 작은 체크를 반복해두면 다음 글의 `hello-world` 실습도 훨씬 더 안정적으로 따라오실 수 있습니다.
