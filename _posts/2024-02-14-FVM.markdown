# FVM으로 Flutter 버전 관리하기: 프로젝트마다 SDK 고정하기

> FVM으로 프로젝트별 Flutter SDK 버전을 고정하고 팀 개발에서 버전 충돌을 줄이는 방법을 설명합니다.

Flutter를 혼자 공부할 때는 최신 SDK 하나만 설치해도 큰 문제가 없어 보입니다. 하지만 프로젝트가 여러 개가 되거나 팀으로 개발하기 시작하면 Flutter 버전 차이가 생각보다 큰 문제를 만듭니다. 내 컴퓨터에서는 빌드되는데 다른 사람 컴퓨터에서는 실패하거나, 패키지 버전은 그대로인데 Flutter SDK만 달라져서 경고와 에러가 생길 수 있습니다.

FVM은 Flutter Version Management의 약자로, 프로젝트별로 Flutter SDK 버전을 고정해주는 도구입니다. Node.js의 nvm, Ruby의 rbenv처럼 Flutter에서도 버전 관리가 필요할 때 사용하는 도구라고 이해하면 쉽습니다.

## FVM이 필요한 이유

예를 들어 A 프로젝트는 Flutter 3.19에서 안정적으로 운영 중이고, B 프로젝트는 Flutter 3.24를 사용한다고 해봅시다. 전역 Flutter를 하나만 사용하면 프로젝트를 옮길 때마다 SDK를 바꿔야 합니다. 실수로 A 프로젝트를 최신 Flutter로 빌드했다가 패키지 호환성 문제가 생길 수도 있습니다.

FVM을 사용하면 프로젝트 루트에 설정 파일을 두고, 해당 프로젝트에서 사용할 Flutter 버전을 명확히 지정할 수 있습니다.

```text
my_app/
  .fvm/
  .fvmrc
  pubspec.yaml
```

이렇게 해두면 "이 프로젝트는 어떤 Flutter 버전으로 실행해야 하는가"가 코드 저장소 안에 남습니다.

## FVM 설치

FVM은 Dart pub global로 설치할 수 있습니다.

```powershell
dart pub global activate fvm
```

설치 후 다음 명령으로 확인합니다.

```powershell
fvm --version
```

명령을 찾을 수 없다면 Dart pub cache의 bin 경로가 PATH에 없을 수 있습니다. Windows에서는 보통 다음 경로를 확인합니다.

```text
C:\Users\사용자명\AppData\Local\Pub\Cache\bin
```

PATH를 수정한 뒤에는 PowerShell을 새로 열어야 적용됩니다.

## 프로젝트에 Flutter 버전 지정하기

프로젝트 루트에서 사용할 Flutter 버전을 설치하고 지정합니다.

```powershell
fvm install 3.24.5
fvm use 3.24.5
```

`fvm use`를 실행하면 프로젝트에 FVM 설정이 생성됩니다. 이후 Flutter 명령은 다음처럼 실행합니다.

```powershell
fvm flutter pub get
fvm flutter run
fvm flutter test
```

처음에는 명령 앞에 `fvm`을 붙이는 것이 귀찮아 보이지만, 이 습관이 버전 불일치 문제를 줄여줍니다.

## 현재 프로젝트 버전 확인

현재 프로젝트가 어떤 Flutter 버전을 사용하는지 확인하려면 다음 명령을 사용합니다.

```powershell
fvm flutter --version
```

전역 Flutter와 비교해볼 수도 있습니다.

```powershell
flutter --version
fvm flutter --version
```

두 결과가 달라도 이상한 것이 아닙니다. 전역 Flutter는 시스템 기본값이고, `fvm flutter`는 현재 프로젝트가 지정한 버전입니다. 프로젝트 작업에서는 후자가 더 중요합니다.

## IDE 설정

VS Code를 사용한다면 `.vscode/settings.json`에 Flutter SDK 경로를 지정할 수 있습니다.

```json
{
  "dart.flutterSdkPath": ".fvm/flutter_sdk"
}
```

Android Studio에서도 Flutter SDK Path를 프로젝트의 `.fvm/flutter_sdk`로 맞추는 것이 좋습니다. 터미널에서는 `fvm flutter`로 잘 되는데 IDE에서만 분석 오류가 난다면 IDE가 전역 SDK를 보고 있을 가능성이 있습니다.

## 팀 프로젝트에서의 규칙

FVM 설정 파일은 저장소에 포함하고, 실제 SDK 파일은 포함하지 않는 것이 일반적입니다. `.fvm/flutter_sdk`는 로컬에 설치된 SDK 링크이므로 Git에 올릴 필요가 없습니다.

```gitignore
.fvm/flutter_sdk
```

반대로 `.fvmrc`나 FVM 설정 파일은 팀원들이 같은 버전을 알 수 있도록 커밋하는 편이 좋습니다.

새로 프로젝트를 받은 팀원은 다음처럼 실행하면 됩니다.

```powershell
fvm install
fvm flutter pub get
```

`fvm install`은 프로젝트 설정을 보고 필요한 Flutter 버전을 설치합니다.

## 버전 업그레이드 순서

Flutter 버전을 올릴 때는 무작정 최신으로 바꾸기보다 안전한 순서로 진행합니다.

```powershell
fvm install 3.27.0
fvm use 3.27.0
fvm flutter clean
fvm flutter pub get
fvm flutter test
```

그다음 앱을 실행해서 빌드 오류, deprecated 경고, UI 깨짐을 확인합니다. 패키지들이 새 SDK와 맞지 않을 수 있으므로 `pubspec.lock` 변경도 같이 살펴봐야 합니다.

## 자주 만나는 문제

`fvm` 명령을 찾을 수 없다면 PATH 문제입니다. Dart pub cache bin 경로가 등록되어 있는지 확인합니다.

IDE에서만 에러가 난다면 IDE의 Flutter SDK Path가 `.fvm/flutter_sdk`인지 확인합니다.

CI에서 빌드가 실패한다면 GitHub Actions 같은 CI 환경도 같은 Flutter 버전을 설치하도록 맞춰야 합니다. 로컬만 FVM으로 고정하고 CI는 최신 Flutter를 쓰면 다시 버전 불일치가 생깁니다.

## 정리

FVM은 Flutter 프로젝트의 SDK 버전을 명확하게 고정해주는 도구입니다. 개인 프로젝트에서도 유용하지만, 팀 프로젝트와 CI가 있는 프로젝트에서는 특히 중요합니다. 개발환경 설정은 [Flutter 개발환경 설정 글](/flutter/settings)에서 잡고, 프로젝트별 버전 관리는 FVM으로 고정하면 훨씬 안정적인 Flutter 작업 환경을 만들 수 있습니다.
