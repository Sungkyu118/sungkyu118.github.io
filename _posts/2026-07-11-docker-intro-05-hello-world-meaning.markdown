Docker를 처음 설치한 뒤 가장 많이 실행해보는 명령어가 바로 `docker run hello-world`입니다. 겉보기에는 정말 간단합니다. 한 줄만 입력하면 메시지가 출력되고 끝나기 때문입니다. 그래서 많은 분들이 이 명령을 "설치 확인용 예제" 정도로만 보고 넘기곤 합니다. 그런데 사실 이 짧은 실습 안에는 Docker의 핵심 흐름이 꽤 많이 들어 있습니다. 이미지가 없으면 내려받고, 컨테이너를 만들고, 실행하고, 로그를 남기고, 종료하는 과정이 모두 이 안에 들어 있기 때문입니다.

이번 글에서는 `hello-world`를 단순히 성공 여부만 보는 실습으로 다루지 않겠습니다. 대신 이 명령 뒤에서 어떤 단계가 실제로 일어나는지, 왜 출력이 한 번 나오고 끝나는지, 실행 후에는 어떤 상태를 확인할 수 있는지까지 자세히 설명드리겠습니다. 이 흐름을 이해해두면 이후 `docker run`, `docker ps`, `docker logs` 같은 명령이 훨씬 덜 기계적으로 느껴집니다.

## 먼저 이해해야 할 핵심 관점

이번 글의 핵심은 `docker run hello-world`가 단순 실행이 아니라 여러 단계를 한 번에 수행하는 명령이라는 점입니다. 입문자분들은 흔히 `run`을 "실행만 한다"라고 받아들이기 쉽습니다. 하지만 실제로는 이미지 확인, 필요 시 pull, 컨테이너 생성, 컨테이너 시작, 출력 연결 같은 과정이 이어집니다. 즉, 한 줄 뒤에 생각보다 많은 일이 숨어 있습니다.

또 하나 중요한 점은 `hello-world` 컨테이너가 "계속 떠 있는 서비스"가 아니라는 사실입니다. 메시지를 출력하는 것이 역할의 전부이기 때문에, 일을 마치면 바로 종료됩니다. 이 특징을 이해하지 못하면 `docker ps`에 안 보이는 이유를 이상하게 느끼실 수 있습니다. 하지만 오히려 이 덕분에 실행과 종료 흐름을 아주 선명하게 관찰하기 좋은 예제가 됩니다.

## 가장 먼저 실행해볼 명령어

아래 명령어가 이번 글의 출발점입니다.

```bash
docker run hello-world
```

처음 실행하면 보통 Docker가 `hello-world` 이미지를 로컬에서 찾습니다. 로컬에 없으면 Docker Hub 같은 레지스트리에서 이미지를 내려받습니다. 그 다음 그 이미지를 기반으로 컨테이너를 하나 만들고, 그 안에서 아주 짧은 프로그램을 실행합니다. 그 프로그램은 안내 메시지를 출력한 뒤 역할이 끝나므로 바로 종료됩니다. 그래서 명령어는 짧지만, 실제로는 이미지와 컨테이너의 차이, 실행 흐름, 종료 상태 확인까지 한 번에 경험할 수 있습니다.

초보자분들이 여기서 가장 많이 오해하는 부분은 "이미지가 실행되었다"라고 말하는 것입니다. 더 정확히는 이미지를 기반으로 컨테이너가 실행된 것입니다. 이 차이를 머릿속에서 계속 유지해보시면 좋겠습니다.

## 실행 뒤에는 무엇을 확인하면 좋을까요?

명령어가 성공했다면 바로 아래 흐름을 한 번 확인해보시는 것이 좋습니다.

```bash
docker ps
docker ps -a
```

`docker ps`는 현재 실행 중인 컨테이너만 보여줍니다. 그런데 `hello-world`는 메시지를 출력하고 바로 종료되므로, 대부분 여기에는 안 보일 것입니다. 처음 보는 분들은 여기서 "방금 실행했는데 왜 안 보이지?" 하고 헷갈리기 쉽습니다. 하지만 이것이 오히려 정상입니다. 실행은 했지만 이미 끝난 상태이기 때문입니다.

반면 `docker ps -a`는 종료된 컨테이너까지 보여줍니다. 그래서 `hello-world` 컨테이너의 흔적을 여기서 확인할 수 있습니다. 이 흐름은 아주 중요합니다. "실행 중인지", "한 번 실행하고 끝난 것인지", "실패로 종료된 것인지"를 확인할 때 앞으로 계속 쓰게 되는 기본 감각이기 때문입니다.

## 로그는 왜 같이 봐야 할까요?

실행 뒤에는 로그도 같이 확인해보시면 좋습니다.

```bash
docker logs <컨테이너 이름 또는 ID>
```

`hello-world`는 표준 출력으로 메시지를 남기고 종료하기 때문에, 로그를 보면 방금 터미널에서 봤던 내용과 거의 같은 메시지를 다시 확인할 수 있습니다. 초보자분들이 여기서 얻어가셔야 할 가장 중요한 감각은 "컨테이너가 종료됐더라도 로그는 따로 확인할 수 있다"는 점입니다. 나중에 애플리케이션 컨테이너가 바로 죽어버릴 때도, 가장 먼저 로그를 확인하는 습관이 아주 중요합니다.

특히 실무에서는 브라우저 화면이 안 뜨거나, API가 연결되지 않거나, 프로그램이 실행되자마자 종료되는 상황이 흔합니다. 이때 무작정 컨테이너를 다시 띄우기만 하면 원인을 놓치기 쉽습니다. 그래서 지금 `hello-world`처럼 단순한 예제에서도 로그 보는 흐름을 같이 익혀두는 것이 좋습니다.

## 왜 hello-world는 계속 떠 있지 않을까요?

이 부분도 입문자분들이 아주 자주 질문하시는 지점입니다. 많은 분들이 Docker를 처음 배우면 "컨테이너는 서버처럼 계속 돌아가는 것"이라고 생각합니다. 물론 그런 컨테이너도 많습니다. 예를 들어 Nginx, MySQL, Redis 같은 컨테이너는 서비스 프로세스가 계속 살아 있어야 하므로 보통 계속 실행 중입니다.

하지만 `hello-world`는 역할이 다릅니다. 이 컨테이너는 Docker 실행이 정상적으로 되었는지 보여주는 짧은 메시지를 출력하는 것이 목적입니다. 해야 할 일이 끝났으니 자연스럽게 종료됩니다. 즉, 컨테이너는 "항상 오래 살아 있는 존재"가 아니라, 어떤 프로세스를 실행하는 단위라고 이해하시는 것이 더 정확합니다. 실행할 프로세스가 끝나면 컨테이너도 끝날 수 있습니다.

## 한 단계 더 나아간 간단한 실습

`hello-world` 흐름을 조금 더 확실하게 체험하고 싶다면 아래처럼 아주 짧은 명령도 같이 해보시면 좋습니다.

```bash
docker run --rm alpine echo "Docker 실습이 잘 되고 있습니다."
```

이 예제도 매우 짧게 실행되고 끝납니다. `alpine` 이미지를 내려받아 아주 가벼운 리눅스 환경에서 `echo` 명령을 실행한 뒤 종료하는 흐름입니다. 여기서 중요한 점은, Docker가 꼭 장시간 실행되는 서비스만 다루는 도구는 아니라는 사실입니다. 이렇게 짧은 명령을 실행하는 용도로도 사용할 수 있습니다.

또 `--rm` 옵션을 같이 보시면 좋습니다. 이 옵션은 컨테이너 실행이 끝난 뒤 자동으로 컨테이너를 지워줍니다. 지금은 이 옵션을 외우는 것이 중요하지는 않지만, "실행 후 흔적을 남길 수도 있고 자동 정리할 수도 있다"는 감각 정도는 잡아두시면 좋겠습니다.

## 초보자가 자주 하는 실수와 오해

가장 흔한 실수는 `docker ps`만 보고 "실행이 안 됐다"고 판단하는 것입니다. 하지만 `hello-world`처럼 원래 바로 종료되는 컨테이너는 `docker ps -a`와 `docker logs`를 같이 봐야 합니다. 이 차이를 모르고 있으면 정상 종료도 실패처럼 느껴질 수 있습니다.

또 다른 흔한 오해는 `hello-world`가 너무 단순하니 별 의미 없는 예제라고 생각하는 것입니다. 물론 실제 서비스 배포와는 거리가 멉니다. 하지만 Docker 입문에서는 오히려 이 정도로 단순한 예제가 좋습니다. 이미지 pull, 컨테이너 생성, 실행, 로그, 종료라는 최소한의 핵심 흐름이 잡음 없이 드러나기 때문입니다. 이 흐름만 확실히 익혀도 이후의 대부분 Docker 실습이 훨씬 덜 낯설게 느껴집니다.

## 오늘 내용 정리

이번 글에서는 처음 실행하는 `hello-world`는 무엇을 보여줄까요?라는 질문을 중심으로, `docker run hello-world` 한 줄 뒤에서 이미지 확인, 이미지 pull, 컨테이너 생성, 실행, 출력, 종료가 어떻게 이어지는지 정리해보았습니다. 지금 단계에서는 이 명령을 한 번 성공시키는 것보다, 왜 실행 뒤에 컨테이너가 바로 안 보일 수 있는지, 왜 `docker ps -a`와 `docker logs`를 같이 봐야 하는지를 이해하는 것이 더 중요합니다.

가능하시면 지금은 실제로 `docker run hello-world`, `docker ps`, `docker ps -a`, `docker logs` 흐름을 직접 한 번 따라가 보시면 좋겠습니다. 같은 명령을 손으로 여러 번 반복해보면, Docker가 이미지를 다루는 방식과 컨테이너를 다루는 방식이 훨씬 더 몸에 익기 시작합니다. 그 경험이 쌓이면 이후 `docker run` 옵션이나 Compose 같은 주제로 넘어갈 때도 훨씬 덜 막히게 됩니다.
