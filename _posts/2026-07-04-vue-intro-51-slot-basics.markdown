# Vue 입문 51: slot으로 컴포넌트의 빈칸을 부모가 채우는 방식 이해하기

props는 부모가 자식에게 데이터를 전달하는 방식입니다. 하지만 어떤 경우에는 단순 데이터보다 "화면 조각" 자체를 자식 안에 넣고 싶습니다. 예를 들어 카드 컴포넌트가 테두리와 여백은 제공하되, 카드 안의 제목과 본문은 부모가 자유롭게 작성하게 하고 싶을 수 있습니다. 이때 사용하는 것이 slot입니다.

slot은 자식 컴포넌트 안에 만들어둔 빈자리입니다. 부모는 자식 컴포넌트 태그 사이에 내용을 작성하고, 자식은 `<slot />` 위치에 그 내용을 표시합니다. 그래서 slot은 컴포넌트를 더 유연하게 합성하는 도구라고 볼 수 있습니다.

입문 단계에서는 slot을 "props보다 고급 문법"으로만 생각하지 않는 것이 좋습니다. props는 값 전달에 좋고, slot은 콘텐츠 전달에 좋습니다. 버튼 문구처럼 간단한 텍스트도 slot으로 받을 수 있고, 카드 본문처럼 복잡한 HTML 조각도 slot으로 받을 수 있습니다.

## 이번 글에서 먼저 잡을 관점

이번 구간부터는 Vue를 단순히 한 파일 안에서 쓰는 단계에서 벗어나, 여러 컴포넌트가 함께 동작하는 구조를 다룹니다. 그래서 문법 하나만 보는 것보다 역할과 책임을 같이 보는 것이 중요합니다. 부모 컴포넌트가 무엇을 알고 있어야 하는지, 자식 컴포넌트는 어디까지 책임져야 하는지, 사용자의 행동을 어느 방향으로 전달해야 하는지 계속 질문하면서 읽어보시면 좋습니다.

컴포넌트 설계는 처음부터 완벽하게 나누는 일이 아닙니다. 작은 화면을 만들고, 반복되는 부분이나 책임이 분명한 부분을 발견하고, 그때 적절히 분리하는 과정에 가깝습니다. 이 글의 예제도 정답이라기보다 기준을 잡기 위한 출발점으로 봐주세요. 직접 이름을 바꿔보고, props를 하나 추가해보고, 이벤트 흐름을 바꿔보면 훨씬 오래 기억에 남습니다.

## 작은 실습으로 확인해보기

아래 예제는 카드 껍데기는 자식이 제공하고, 카드 안의 실제 내용은 부모가 채웁니다.

```vue
<!-- BaseCard.vue -->
<template>
  <article class="card">
    <slot />
  </article>
</template>

<style scoped>
.card {
  padding: 20px;
  border: 1px solid #d1d5db;
  border-radius: 12px;
}
</style>

<!-- Parent.vue -->
<template>
  <BaseCard>
    <h2>Vue slot 배우기</h2>
    <p>카드 내부 콘텐츠는 부모가 자유롭게 작성합니다.</p>
    <button>자세히 보기</button>
  </BaseCard>
</template>
```

## 코드가 움직이는 순서

`BaseCard`는 카드 스타일과 구조만 제공합니다. `<slot />`은 부모가 넣은 콘텐츠가 들어갈 자리입니다. 부모는 `<BaseCard>`와 `</BaseCard>` 사이에 제목, 문단, 버튼을 작성합니다. 이 내용이 자식의 slot 위치에 렌더링됩니다.

여기서 중요한 것은 코드 줄 수보다 의도입니다. 컴포넌트를 나누면 파일은 늘어나지만, 각 파일이 맡는 역할이 선명해져야 합니다. 부모는 전체 상태와 흐름을 관리하고, 자식은 자신이 맡은 UI 조각을 표현하거나 사용자 행동을 이벤트로 알려주는 식으로 역할을 나누면 디버깅이 훨씬 쉬워집니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: slot은 부모 템플릿의 콘텐츠를 자식 내부 위치에 넣는 방식입니다. 자식이 부모의 상태를 직접 소유하는 것은 아닙니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: slot으로 너무 많은 구조를 넘기면 자식 컴포넌트의 역할이 애매해질 수 있습니다. 자식이 제공할 구조와 부모가 채울 내용을 구분하세요. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: slot이 비어 있을 때 기본 콘텐츠를 제공할 수도 있습니다. 빈 상태를 어떻게 보일지 고려하면 컴포넌트가 더 친절해집니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.

컴포넌트 관련 오류는 한 파일만 봐서는 바로 보이지 않을 때가 많습니다. 부모가 넘기는 prop 이름, 자식이 선언한 prop 이름, 자식이 emit하는 이벤트 이름, 부모가 듣는 이벤트 이름을 한 줄씩 맞춰보는 습관이 필요합니다. 브라우저 콘솔의 Vue warning도 그냥 넘기지 말고, 어떤 컴포넌트에서 발생했는지 확인해보시면 좋습니다.

## 실무에서 생각할 점

slot은 유연하지만, 유연성이 너무 커지면 컴포넌트 사용법이 흔들릴 수 있습니다. 카드, 모달, 레이아웃처럼 껍데기는 공통이고 안쪽 콘텐츠가 다양한 경우에 특히 잘 맞습니다.

실무에서는 컴포넌트가 "동작한다"보다 "변경에 견딘다"가 더 중요해집니다. 요구사항은 계속 바뀌고, 디자인도 바뀌고, 같은 컴포넌트를 다른 화면에서 쓰고 싶어질 수 있습니다. 그래서 처음부터 모든 것을 일반화하려고 하기보다, 현재 책임을 명확히 하고 나중에 반복이 보일 때 재사용성을 높이는 방향이 안전합니다.
