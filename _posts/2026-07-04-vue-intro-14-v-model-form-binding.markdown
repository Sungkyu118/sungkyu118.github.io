사용자가 입력하는 값은 프론트엔드에서 가장 자주 다루는 상태 중 하나입니다. 검색어, 로그인 이메일, 체크박스 동의 여부, 선택한 카테고리처럼 입력값은 화면에 보이면서 동시에 JavaScript 상태로도 필요합니다. Vue의 `v-model`은 이런 입력 요소와 상태를 양방향으로 연결해줍니다.

양방향이라는 말은 입력창에서 사용자가 값을 바꾸면 Vue 상태가 바뀌고, Vue 상태를 코드에서 바꾸면 입력창에 보이는 값도 바뀐다는 뜻입니다. 이 흐름을 직접 `value`와 `input` 이벤트로 구현할 수도 있지만, `v-model`을 쓰면 기본적인 연결을 간결하게 표현할 수 있습니다.

다만 `v-model`이 편하다고 해서 모든 폼 문제가 자동으로 해결되는 것은 아닙니다. 입력값은 문자열로 들어오는 경우가 많고, 체크박스와 select는 자료형과 초기값에 주의해야 합니다. 검증, 에러 표시, 제출 중 비활성화 같은 흐름은 별도로 설계해야 합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 텍스트 입력, 체크박스, 선택 상자를 한 번에 보여줍니다. 입력값이 아래 미리보기 영역에 즉시 반영됩니다.

{% raw %}
```vue
<script setup>
import { ref } from 'vue'

const email = ref('')
const agreed = ref(false)
const role = ref('reader')
</script>

<template>
  <form>
    <label>
      이메일
      <input v-model="email" type="email" />
    </label>

    <label>
      <input v-model="agreed" type="checkbox" />
      약관에 동의합니다
    </label>

    <label>
      역할
      <select v-model="role">
        <option value="reader">독자</option>
        <option value="writer">작성자</option>
      </select>
    </label>
  </form>

  <pre>{{ { email, agreed, role } }}</pre>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`email`은 문자열 입력과 연결됩니다. `agreed`는 체크박스라서 boolean 값으로 다루는 것이 자연스럽습니다. `role`은 select의 선택된 option value와 연결됩니다. 사용자가 값을 바꿀 때마다 상태가 즉시 바뀌고, 상태가 바뀌므로 미리보기 영역도 갱신됩니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 숫자를 입력받아도 기본 input 값은 문자열인 경우가 많습니다. 계산에 사용할 값이라면 `.number` 수식어나 명시적인 변환을 고려해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 체크박스 초기값을 문자열 `"false"`로 두면 true처럼 취급되어 헷갈릴 수 있습니다. boolean은 실제 boolean으로 관리해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: `v-model`은 입력 연결을 편하게 해줄 뿐, 이메일 형식 검증이나 서버 제출 오류 처리는 직접 구현해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

`v-model`은 폼을 빠르게 만들 때 매우 편합니다. 하지만 큰 폼에서는 모든 입력을 한 컴포넌트에 두면 상태가 복잡해집니다. 입력 컴포넌트 분리, 검증 로직 분리, 제출 상태 관리가 필요해지는 시점에는 `v-model`을 기반으로 하되 구조를 더 세심하게 잡아야 합니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
