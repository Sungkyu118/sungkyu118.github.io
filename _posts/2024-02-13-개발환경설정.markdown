# Flutter 개발환경 설정: SDK, Android Studio, 에뮬레이터까지

> Flutter SDK 설치부터 Android Studio, 에뮬레이터, flutter doctor 점검까지 입문자가 막히는 지점을 함께 정리합니다.

Flutter를 처음 시작할 때 가장 많이 막히는 부분은 Dart 문법이 아니라 개발환경 설정입니다. 예제 코드를 따라 치기도 전에 `flutter doctor`에서 빨간 표시가 나오고, Android SDK 경로를 못 찾고, 에뮬레이터가 실행되지 않으면 시작부터 지치기 쉽습니다. 하지만 개발환경은 한 번 제대로 잡아두면 이후 학습 속도가 훨씬 빨라집니다.

이 글에서는 Windows 기준으로 Flutter SDK 설치, PATH 설정, Android Studio 설치, 에뮬레이터 실행, `flutter doctor` 확인까지 단계별로 정리합니다. macOS나 Linux도 큰 흐름은 비슷하지만, 경로와 권한 설정이 다를 수 있습니다.

## Flutter 개발에 필요한 구성요소

Flutter 앱을 만들려면 최소한 아래 도구들이 필요합니다.

- Flutter SDK
- Dart SDK
- Android Studio 또는 VS Code
- Android SDK
- Android Emulator 또는 실제 Android 기기

Dart SDK는 Flutter SDK 안에 포함되어 있으므로 보통 Dart를 따로 설치하지 않아도 됩니다. 핵심은 Flutter SDK가 정상 설치되고, 터미널에서 `flutter` 명령을 찾을 수 있으며, Android 빌드 도구가 연결되어 있는지입니다.

## Flutter SDK 설치

Flutter 공식 사이트에서 Windows용 SDK를 내려받고 원하는 위치에 압축을 풉니다. 예를 들어 다음처럼 둘 수 있습니다.

```text
C:\src\flutter
```

경로에 한글이나 공백이 들어가면 일부 도구에서 문제를 만들 수 있으므로 가능하면 단순한 영문 경로를 추천합니다.

압축을 푼 뒤에는 `bin` 폴더를 PATH에 추가해야 합니다.

```text
C:\src\flutter\bin
```

PowerShell을 새로 열고 다음 명령으로 확인합니다.

```powershell
flutter --version
```

명령을 찾을 수 없다는 메시지가 나오면 PATH가 아직 적용되지 않았거나 경로가 잘못된 것입니다. 터미널을 새로 열어보고, 그래도 안 되면 환경 변수에 등록한 경로가 `flutter\bin`까지 포함하는지 확인합니다.

## flutter doctor 확인

Flutter 설치 후 가장 먼저 실행할 명령은 `flutter doctor`입니다.

```powershell
flutter doctor
```

이 명령은 Flutter 개발에 필요한 도구들이 정상 연결되어 있는지 검사합니다. 처음 실행하면 Android toolchain, Chrome, Visual Studio, Android Studio, connected device 항목 중 일부가 경고로 나올 수 있습니다. 모든 항목이 반드시 초록색이어야 시작할 수 있는 것은 아니지만, Android 앱을 만들려면 Android toolchain과 Android Studio 관련 항목은 해결하는 편이 좋습니다.

```text
[✓] Flutter
[✓] Android toolchain
[✓] Android Studio
[✓] Connected device
```

경고가 나왔을 때는 메시지를 그냥 넘기지 말고, 어떤 항목이 문제인지 먼저 읽어야 합니다. `cmdline-tools component is missing`이라면 Android SDK Command-line Tools가 빠진 것이고, `Android license status unknown`이라면 라이선스 동의가 필요한 상황입니다.

```powershell
flutter doctor --android-licenses
```

라이선스 질문이 나오면 내용을 확인하고 `y`로 동의하면 됩니다.

## Android Studio 설치와 SDK 설정

Android Studio를 설치한 뒤 `Settings > Languages & Frameworks > Android SDK`로 이동합니다. 여기서 SDK Platforms와 SDK Tools를 확인합니다.

필수로 확인할 항목은 다음과 같습니다.

- Android SDK Platform
- Android SDK Build-Tools
- Android SDK Command-line Tools
- Android Emulator
- Platform-Tools

Command-line Tools가 빠져 있으면 `flutter doctor`에서 경고가 나올 수 있습니다. SDK 경로는 보통 다음 위치입니다.

```text
C:\Users\사용자명\AppData\Local\Android\Sdk
```

환경이 꼬였을 때는 Flutter가 어떤 Android SDK를 보고 있는지 확인할 수 있습니다.

```powershell
flutter config --list
```

필요하면 명시적으로 지정합니다.

```powershell
flutter config --android-sdk "C:\Users\사용자명\AppData\Local\Android\Sdk"
```

## 에뮬레이터 만들기

Android Studio에서 `Device Manager`를 열고 새 가상 기기를 만듭니다. Pixel 계열 기기를 선택하고, 적절한 Android 시스템 이미지를 내려받으면 됩니다. 처음에는 최신 버전만 고집하기보다 안정적인 API 버전을 하나 선택해도 충분합니다.

에뮬레이터를 실행한 뒤 터미널에서 기기가 보이는지 확인합니다.

```powershell
flutter devices
```

기기가 보이면 앱을 실행할 수 있습니다.

```powershell
flutter run
```

에뮬레이터가 너무 느리다면 하드웨어 가상화가 꺼져 있을 수 있습니다. BIOS에서 virtualization이 켜져 있는지, Windows 기능에서 Hyper-V 관련 설정이 충돌하지 않는지 확인해야 할 수 있습니다.

## 첫 프로젝트 만들기

환경이 준비되었다면 테스트 프로젝트를 만들어봅니다.

```powershell
flutter create hello_flutter
cd hello_flutter
flutter run
```

처음 빌드는 Gradle과 Android 의존성을 내려받기 때문에 오래 걸릴 수 있습니다. 이 과정에서 네트워크가 느리거나 사내망 프록시가 있으면 실패할 수 있습니다. 첫 빌드가 오래 걸리는 것은 자연스러운 일이므로 터미널 로그를 보면서 기다리면 됩니다.

## VS Code를 사용할 때

VS Code를 사용한다면 Flutter 확장과 Dart 확장을 설치합니다. 프로젝트 폴더를 열고 `lib/main.dart`에서 F5를 누르면 디버깅 실행이 가능합니다. 다만 Android SDK 자체는 Android Studio를 통해 설치하는 것이 가장 편합니다.

여러 프로젝트에서 Flutter 버전을 다르게 써야 한다면 [FVM 글](/flutter/fvm)을 함께 보면 좋습니다. 개발환경 설정은 전역 Flutter를 준비하는 과정이고, FVM은 프로젝트별 Flutter 버전을 고정하는 과정입니다.

## 자주 만나는 문제

`flutter` 명령을 찾을 수 없다면 PATH 문제입니다. Flutter SDK 위치가 아니라 `flutter\bin` 경로를 넣었는지 확인합니다.

`Android license status unknown`이 나오면 `flutter doctor --android-licenses`를 실행합니다.

`No devices found`가 나오면 에뮬레이터가 실행 중인지, 실제 기기라면 USB 디버깅이 켜져 있는지 확인합니다.

Gradle 빌드가 실패하면 인터넷 연결, JDK 버전, Android Gradle Plugin 버전이 원인일 수 있습니다. 처음에는 새 프로젝트를 만들어 기본 앱이 실행되는지 확인하면 환경 문제와 프로젝트 문제를 분리할 수 있습니다.

## 정리

Flutter 개발환경 설정은 Flutter SDK, PATH, Android Studio, Android SDK, 에뮬레이터가 서로 연결되는 과정입니다. 막히면 `flutter doctor`를 기준으로 하나씩 해결하면 됩니다. 처음에는 시간이 걸리지만, 기본 앱이 한 번 실행되면 이후에는 위젯, 라우팅, 상태관리 같은 실제 Flutter 학습에 집중할 수 있습니다.
