모달은 slot을 연습하기에 좋은 컴포넌트입니다. 모달의 바깥 구조, 배경, 닫기 버튼, 기본 스타일은 여러 화면에서 비슷합니다. 하지만 모달 안의 제목, 본문, 하단 버튼은 상황마다 달라집니다. 이때 slot을 사용하면 공통 구조와 개별 콘텐츠를 자연스럽게 분리할 수 있습니다.

모달을 만들 때는 단순히 화면 가운데 박스를 띄우는 것만 생각하면 부족합니다. 닫기 이벤트를 부모에게 알려야 하고, 배경 클릭이나 ESC 닫기 같은 정책도 고민해야 합니다. 접근성 측면에서는 `role="dialog"`, `aria-modal="true"`, 제목 연결, 포커스 관리 같은 요소도 중요합니다. 입문 글에서는 모든 접근성 처리를 완벽히 구현하지 않더라도, 처음부터 고려 지점을 알고 가는 것이 좋습니다.

slot 기반 모달의 핵심은 자식이 레이아웃을 제공하고 부모가 내용을 채운다는 점입니다. 자식 모달은 닫기 요청을 emit으로 올리고, 부모는 실제 열림 상태를 바꿉니다. 이렇게 하면 모달 컴포넌트는 특정 기능에 묶이지 않고 여러 화면에서 재사용할 수 있습니다.

## 이번 글에서 먼저 잡을 관점

이번 구간부터는 Vue를 단순히 한 파일 안에서 쓰는 단계에서 벗어나, 여러 컴포넌트가 함께 동작하는 구조를 다룹니다. 그래서 문법 하나만 보는 것보다 역할과 책임을 같이 보는 것이 중요합니다. 부모 컴포넌트가 무엇을 알고 있어야 하는지, 자식 컴포넌트는 어디까지 책임져야 하는지, 사용자의 행동을 어느 방향으로 전달해야 하는지 계속 질문하면서 읽어보시면 좋습니다.

컴포넌트 설계는 처음부터 완벽하게 나누는 일이 아닙니다. 작은 화면을 만들고, 반복되는 부분이나 책임이 분명한 부분을 발견하고, 그때 적절히 분리하는 과정에 가깝습니다. 이 글의 예제도 정답이라기보다 기준을 잡기 위한 출발점으로 봐주세요. 직접 이름을 바꿔보고, props를 하나 추가해보고, 이벤트 흐름을 바꿔보면 훨씬 오래 기억에 남습니다.

## 작은 실습으로 확인해보기

아래 예제는 header, default, footer slot과 close 이벤트를 가진 기본 모달입니다.

```vue
<!-- BaseModal.vue -->
<script setup>
const emit = defineEmits(['close'])
</script>

<template>
  <div class="backdrop" @click.self="emit('close')">
    <section class="modal" role="dialog" aria-modal="true">
      <header class="modal-header">
        <slot name="header" />
        <button type="button" @click="emit('close')">닫기</button>
      </header>

      <main class="modal-body">
        <slot />
      </main>

      <footer class="modal-footer">
        <slot name="footer" />
      </footer>
    </section>
  </div>
</template>

<!-- Parent.vue -->
<template>
  <BaseModal @close="isOpen = false">
    <template #header>
      <h2>프로필 수정</h2>
    </template>

    <p>프로필 정보를 수정하시겠습니까?</p>

    <template #footer>
      <button @click="isOpen = false">취소</button>
      <button>저장</button>
    </template>
  </BaseModal>
</template>
```

## 코드가 움직이는 순서

모달 자식 컴포넌트는 배경과 패널 구조를 담당합니다. `@click.self`는 배경 자신을 클릭했을 때만 닫기 이벤트를 올리도록 합니다. 부모는 header, body, footer 콘텐츠를 slot으로 채웁니다. 닫기 버튼이나 배경 클릭은 `close` 이벤트를 올리고, 부모가 `isOpen` 상태를 false로 바꿉니다.

여기서 중요한 것은 코드 줄 수보다 의도입니다. 컴포넌트를 나누면 파일은 늘어나지만, 각 파일이 맡는 역할이 선명해져야 합니다. 부모는 전체 상태와 흐름을 관리하고, 자식은 자신이 맡은 UI 조각을 표현하거나 사용자 행동을 이벤트로 알려주는 식으로 역할을 나누면 디버깅이 훨씬 쉬워집니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 모달 내부 버튼 클릭이 배경 클릭으로 전파되어 닫히지 않도록 이벤트 처리에 주의해야 합니다. 예제의 `@click.self`는 그 문제를 줄여줍니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: 실무 모달은 포커스 트랩, ESC 키 닫기, 스크롤 잠금까지 고려해야 합니다. 기본 구조를 만든 뒤 접근성을 점진적으로 보강하세요. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: 모달 컴포넌트가 특정 API 저장까지 직접 맡으면 재사용성이 떨어집니다. 저장 버튼 내용과 동작은 부모가 결정하게 하는 편이 좋습니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.

컴포넌트 관련 오류는 한 파일만 봐서는 바로 보이지 않을 때가 많습니다. 부모가 넘기는 prop 이름, 자식이 선언한 prop 이름, 자식이 emit하는 이벤트 이름, 부모가 듣는 이벤트 이름을 한 줄씩 맞춰보는 습관이 필요합니다. 브라우저 콘솔의 Vue warning도 그냥 넘기지 말고, 어떤 컴포넌트에서 발생했는지 확인해보시면 좋습니다.

## 실무에서 생각할 점

slot 기반 모달은 재사용성이 높습니다. 하지만 너무 많은 정책을 하나의 BaseModal에 넣으면 복잡해질 수 있습니다. 공통 레이아웃과 기본 닫기 흐름은 BaseModal에 두고, 화면별 저장/삭제/검증 흐름은 부모가 처리하는 방식이 좋습니다.

실무에서는 컴포넌트가 "동작한다"보다 "변경에 견딘다"가 더 중요해집니다. 요구사항은 계속 바뀌고, 디자인도 바뀌고, 같은 컴포넌트를 다른 화면에서 쓰고 싶어질 수 있습니다. 그래서 처음부터 모든 것을 일반화하려고 하기보다, 현재 책임을 명확히 하고 나중에 반복이 보일 때 재사용성을 높이는 방향이 안전합니다.
