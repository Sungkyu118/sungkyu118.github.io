Vue에서 조건에 따라 화면을 보여주거나 숨기는 대표 문법은 `v-if`와 `v-show`입니다. 둘 다 겉으로는 비슷해 보입니다. 조건이 true이면 보이고 false이면 안 보입니다. 하지만 내부 동작은 다릅니다. `v-if`는 조건이 false이면 해당 요소를 DOM에 만들지 않거나 제거합니다. `v-show`는 요소를 DOM에는 남겨두고 CSS의 display로 보이거나 숨깁니다.

이 차이는 실제 프로젝트에서 중요합니다. 처음부터 거의 보이지 않을 영역이라면 `v-if`가 자연스럽습니다. 예를 들어 로그인하지 않은 사용자에게만 보이는 안내 문구나, 데이터가 있을 때만 렌더링할 상세 영역은 `v-if`가 좋습니다. 반면 탭 내용처럼 자주 켰다 껐다 하는 UI라면 매번 만들고 제거하는 것보다 `v-show`가 나을 수 있습니다.

`v-else`와 `v-else-if`는 `v-if`와 이어서 조건 분기를 만들 때 사용합니다. 이때 중간에 다른 요소가 끼면 연결이 깨질 수 있으므로 템플릿 구조에 주의해야 합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 로그인 여부와 도움말 표시 여부를 나누어 보여줍니다. 로그인 영역은 `v-if`, 자주 토글하는 도움말은 `v-show`를 사용했습니다.

```vue
<script setup>
import { ref } from 'vue'

const isLoggedIn = ref(false)
const showHelp = ref(false)
</script>

<template>
  <section>
    <p v-if="isLoggedIn">환영합니다. 내 정보를 확인할 수 있습니다.</p>
    <p v-else>로그인이 필요합니다.</p>

    <button @click="showHelp = !showHelp">
      도움말 열기/닫기
    </button>

    <aside v-show="showHelp">
      이 도움말은 자주 토글되므로 DOM에 남겨둔 채 표시만 바꿉니다.
    </aside>
  </section>
</template>
```

## 코드가 움직이는 순서

`isLoggedIn` 값에 따라 첫 번째 문단 또는 두 번째 문단 중 하나만 렌더링됩니다. 반면 `showHelp`로 제어되는 `aside`는 DOM에 남아 있고 display만 바뀝니다. 브라우저 개발자 도구 Elements 탭을 열어 비교해보면 차이를 직접 볼 수 있습니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: `v-if`와 `v-for`를 같은 요소에 함께 쓰면 우선순위와 가독성 문제가 생길 수 있습니다. 조건 필터링은 computed로 빼거나 바깥 template을 활용하는 것이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: `v-show`는 DOM에 남기 때문에 민감한 정보를 숨기는 보안 수단이 될 수 없습니다. 단지 화면 표시만 바꾸는 것입니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: `v-else`는 바로 앞의 `v-if`와 연결되어야 합니다. 중간에 다른 요소가 들어가면 의도대로 동작하지 않습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

간단히 말하면 조건이 자주 바뀌지 않거나 처음부터 만들 필요가 없는 영역은 `v-if`, 자주 표시/숨김을 반복하는 영역은 `v-show`가 편합니다. 하지만 성능보다 먼저 고려할 것은 의미입니다. DOM에 없어야 하는가, 아니면 잠시 숨기면 되는가를 먼저 판단하면 선택이 쉬워집니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
