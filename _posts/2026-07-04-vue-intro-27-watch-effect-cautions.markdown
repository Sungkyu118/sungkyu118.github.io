# Vue 입문 27: watchEffect는 편하지만 언제 위험해질까요?

> watchEffect의 자동 추적 편의성과 그만큼 흐름이 흐려질 수 있는 위험을 함께 이해합니다.

`watchEffect`는 콜백 안에서 사용한 반응형 값을 자동으로 추적합니다. `watch`처럼 어떤 값을 감시할지 명시하지 않아도 됩니다. 그래서 작은 예제에서는 매우 편합니다. 콜백 안에서 `keyword.value`를 읽으면 Vue가 그 값을 의존성으로 보고, 값이 바뀔 때 다시 실행합니다.

하지만 편리함에는 대가가 있습니다. 감시 대상이 코드 안에서 암묵적으로 결정되기 때문에, 콜백이 길어지면 무엇 때문에 다시 실행되는지 파악하기 어려워질 수 있습니다. 특히 여러 상태를 읽고, 그 안에서 또 상태를 바꾸면 흐름이 복잡해집니다.

입문 단계에서는 `watchEffect`를 "간단한 반응형 실험이나 명확한 부수 효과"에 사용하고, 감시 대상이 중요한 코드에서는 `watch`로 명시하는 편이 좋습니다. 팀원이 코드를 읽을 때 어떤 값이 변하면 실행되는지 바로 보여주는 것이 유지보수에 유리합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 이름과 나이를 읽어 소개 문장을 자동으로 갱신합니다. watchEffect가 어떤 값을 읽는지 눈으로 확인해보세요.

{% raw %}
```vue
<script setup>
import { ref, watchEffect } from 'vue'

const name = ref('성규')
const age = ref(20)
const introduction = ref('')

watchEffect(() => {
  introduction.value = `${name.value}님은 ${age.value}살입니다.`
})
</script>

<template>
  <input v-model="name" />
  <input v-model="age" type="number" />
  <p>{{ introduction }}</p>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`watchEffect` 콜백 안에서 `name.value`와 `age.value`를 읽고 있습니다. Vue는 이 둘을 자동으로 추적합니다. 둘 중 하나가 바뀌면 콜백이 다시 실행되어 `introduction`이 갱신됩니다. 이 예제는 작기 때문에 읽기 쉽지만, 콜백이 길어지면 자동 추적 대상이 한눈에 보이지 않을 수 있습니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: watchEffect는 감시 대상이 명시적으로 보이지 않습니다. 중요한 비즈니스 로직에서는 watch가 더 읽기 쉬울 수 있습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 콜백 안에서 많은 반응형 값을 읽으면 예상보다 자주 다시 실행될 수 있습니다. 성능과 API 호출 횟수에 주의해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 비동기 코드와 함께 쓸 때는 이전 실행 결과가 뒤늦게 반영되는 문제를 고려해야 합니다. 실제 검색 API라면 요청 취소나 최신 요청 판별이 필요합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

watchEffect는 빠르게 반응형 흐름을 만들 때 좋습니다. 하지만 프로젝트가 커질수록 명시성이 중요해집니다. "무엇이 바뀔 때 실행되는지 코드만 보고 바로 알 수 있는가?"가 watch와 watchEffect를 선택하는 좋은 기준입니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
