Vue Composition API를 배우다 보면 `ref`와 `reactive` 중 무엇을 써야 할지 자주 고민하게 됩니다. 둘 다 반응형 상태를 만들지만 사용 감각이 다릅니다. ref는 값을 감싸는 상자에 가깝고, reactive는 객체 자체를 반응형 프록시로 만드는 방식입니다.

가장 쉬운 기준은 값의 형태입니다. 숫자, 문자열, boolean처럼 원시 값은 ref가 자연스럽습니다. 객체나 배열도 ref로 다룰 수 있지만, 여러 속성을 하나의 상태 묶음으로 자주 수정한다면 reactive가 읽기 편할 때가 있습니다. 반대로 객체 전체를 새 값으로 자주 교체해야 한다면 ref가 더 단순할 수 있습니다.

정답은 하나가 아닙니다. 중요한 것은 프로젝트 안에서 일관된 기준을 갖는 것입니다. 어떤 팀은 대부분 ref를 사용하고 객체도 ref로 감싸는 방식을 선호합니다. 어떤 팀은 폼 객체는 reactive로 묶습니다. 입문 단계에서는 두 방식의 장단점을 모두 경험해보는 것이 좋습니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 같은 화면에서 ref와 reactive를 각각 어디에 쓰는지 보여줍니다.

{% raw %}
```vue
<script setup>
import { reactive, ref } from 'vue'

const isSaving = ref(false)
const selectedTab = ref('profile')

const profileForm = reactive({
  name: '',
  introduction: ''
})

function saveProfile() {
  isSaving.value = true
  console.log('저장할 값:', profileForm)
  isSaving.value = false
}
</script>

<template>
  <button @click="selectedTab = 'profile'">프로필</button>
  <button @click="selectedTab = 'settings'">설정</button>

  <form v-if="selectedTab === 'profile'" @submit.prevent="saveProfile">
    <input v-model="profileForm.name" placeholder="이름" />
    <textarea v-model="profileForm.introduction" placeholder="소개" />
    <button :disabled="isSaving">
      {{ isSaving ? '저장 중' : '저장' }}
    </button>
  </form>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`isSaving`과 `selectedTab`은 각각 하나의 원시 값이므로 ref로 관리했습니다. `profileForm`은 이름과 소개가 함께 움직이는 폼 상태라 reactive로 묶었습니다. 저장 함수에서는 ref 값은 `.value`로 다루고, reactive 객체는 속성 형태로 다룹니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: ref와 reactive를 섞어 쓰는 것 자체는 문제가 아닙니다. 문제는 기준 없이 섞어서 팀원이 예측하기 어려운 코드가 되는 것입니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: reactive 객체를 구조 분해하면 반응성이 끊긴 것처럼 보일 수 있습니다. 이 부분은 입문자가 자주 헷갈리는 포인트입니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: ref 안에 객체를 넣으면 스크립트에서 `.value`가 한 단계 더 필요합니다. 이 방식이 싫다면 reactive가 더 편할 수 있습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

학습 초반에는 ref를 중심으로 시작하는 편이 단순합니다. `.value` 규칙만 익히면 원시 값과 객체 모두 다룰 수 있기 때문입니다. 이후 폼처럼 속성이 많은 상태를 자주 다루게 되면 reactive를 함께 사용해보세요. 중요한 것은 코드가 읽는 사람에게 의도를 설명해주는가입니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
