# Vue 입문 37: 재사용 가능한 버튼 컴포넌트 만들기

버튼은 가장 단순해 보이지만 컴포넌트 설계를 연습하기에 아주 좋은 주제입니다. 텍스트만 있는 버튼도 있지만, 저장 중에는 로딩 상태가 필요하고, 위험한 동작은 다른 색상이 필요하며, 비활성 상태에서는 클릭을 막아야 합니다. 같은 버튼 스타일을 여러 화면에서 반복한다면 재사용 가능한 버튼 컴포넌트로 분리할 가치가 있습니다.

버튼 컴포넌트를 만들 때 중요한 것은 너무 많은 기능을 처음부터 넣지 않는 것입니다. 색상 종류, 크기, 아이콘 위치, 라우팅, 권한 체크까지 모두 넣으면 버튼 하나가 작은 프레임워크처럼 커집니다. 입문 단계에서는 variant, disabled, loading, slot 정도만 다뤄도 충분합니다.

slot을 사용하면 부모가 버튼 안의 문구를 자유롭게 넣을 수 있습니다. props는 버튼의 상태나 종류를 제어하는 데 사용합니다. click 이벤트는 버튼 내부에서 처리할 수도 있지만, 보통 부모가 실제 행동을 결정해야 하므로 클릭을 emit으로 올리는 구조가 깔끔합니다.

## 이번 글에서 먼저 잡을 관점

이번 구간부터는 Vue를 단순히 한 파일 안에서 쓰는 단계에서 벗어나, 여러 컴포넌트가 함께 동작하는 구조를 다룹니다. 그래서 문법 하나만 보는 것보다 역할과 책임을 같이 보는 것이 중요합니다. 부모 컴포넌트가 무엇을 알고 있어야 하는지, 자식 컴포넌트는 어디까지 책임져야 하는지, 사용자의 행동을 어느 방향으로 전달해야 하는지 계속 질문하면서 읽어보시면 좋습니다.

컴포넌트 설계는 처음부터 완벽하게 나누는 일이 아닙니다. 작은 화면을 만들고, 반복되는 부분이나 책임이 분명한 부분을 발견하고, 그때 적절히 분리하는 과정에 가깝습니다. 이 글의 예제도 정답이라기보다 기준을 잡기 위한 출발점으로 봐주세요. 직접 이름을 바꿔보고, props를 하나 추가해보고, 이벤트 흐름을 바꿔보면 훨씬 오래 기억에 남습니다.

## 작은 실습으로 확인해보기

아래 예제는 기본/위험 버튼 스타일과 로딩 상태를 지원하는 `BaseButton.vue`입니다.

```vue
<!-- BaseButton.vue -->
<script setup>
defineProps({
  variant: {
    type: String,
    default: 'primary'
  },
  loading: {
    type: Boolean,
    default: false
  },
  disabled: {
    type: Boolean,
    default: false
  }
})

const emit = defineEmits(['click'])
</script>

<template>
  <button
    class="base-button"
    :class="`base-button--${variant}`"
    :disabled="disabled || loading"
    @click="emit('click')"
  >
    <span v-if="loading">처리 중...</span>
    <slot v-else />
  </button>
</template>

<style scoped>
.base-button {
  padding: 10px 16px;
  border: 0;
  border-radius: 8px;
  color: white;
}

.base-button--primary {
  background: #42b883;
}

.base-button--danger {
  background: #ef4444;
}
</style>
```

## 코드가 움직이는 순서

`variant`는 버튼의 시각적 종류를 정합니다. `loading`과 `disabled`는 클릭 가능 여부에 영향을 줍니다. 버튼 안의 텍스트는 slot으로 받기 때문에 부모는 `<BaseButton>저장</BaseButton>`처럼 자연스럽게 사용할 수 있습니다. 실제 저장 동작은 부모가 `@click`으로 받아 처리합니다.

여기서 중요한 것은 코드 줄 수보다 의도입니다. 컴포넌트를 나누면 파일은 늘어나지만, 각 파일이 맡는 역할이 선명해져야 합니다. 부모는 전체 상태와 흐름을 관리하고, 자식은 자신이 맡은 UI 조각을 표현하거나 사용자 행동을 이벤트로 알려주는 식으로 역할을 나누면 디버깅이 훨씬 쉬워집니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 버튼 컴포넌트가 실제 API 호출까지 직접 처리하면 재사용성이 떨어집니다. 버튼은 클릭 의도를 알리고, 행동은 부모가 처리하는 편이 좋습니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: loading 상태에서는 클릭을 막아 중복 제출을 방지해야 합니다. 시각적으로만 로딩 표시를 하고 실제 disabled를 빼먹으면 문제가 생길 수 있습니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.
- **확인 포인트**: variant 값을 아무 문자열이나 허용하면 존재하지 않는 클래스가 붙을 수 있습니다. 실무에서는 허용 목록 검증이나 TypeScript 타입을 고려할 수 있습니다. 이 문제는 예제 단계에서는 작게 보일 수 있지만, 컴포넌트가 늘어나면 원인을 찾기 어려운 버그로 커질 수 있습니다. 코드를 작성할 때는 데이터가 어느 컴포넌트에서 시작되고, 어떤 prop이나 event를 통해 이동하며, 어느 컴포넌트가 최종적으로 상태를 바꾸는지 함께 확인해보세요.

컴포넌트 관련 오류는 한 파일만 봐서는 바로 보이지 않을 때가 많습니다. 부모가 넘기는 prop 이름, 자식이 선언한 prop 이름, 자식이 emit하는 이벤트 이름, 부모가 듣는 이벤트 이름을 한 줄씩 맞춰보는 습관이 필요합니다. 브라우저 콘솔의 Vue warning도 그냥 넘기지 말고, 어떤 컴포넌트에서 발생했는지 확인해보시면 좋습니다.

## 실무에서 생각할 점

공통 버튼은 디자인 일관성을 높여줍니다. 하지만 모든 버튼을 하나의 거대한 컴포넌트로 해결하려고 하면 props가 폭발합니다. 공통 규칙은 `BaseButton`에 두고, 특수한 흐름은 별도 컴포넌트나 부모 로직으로 분리하는 것이 좋습니다.

실무에서는 컴포넌트가 "동작한다"보다 "변경에 견딘다"가 더 중요해집니다. 요구사항은 계속 바뀌고, 디자인도 바뀌고, 같은 컴포넌트를 다른 화면에서 쓰고 싶어질 수 있습니다. 그래서 처음부터 모든 것을 일반화하려고 하기보다, 현재 책임을 명확히 하고 나중에 반복이 보일 때 재사용성을 높이는 방향이 안전합니다.
