Vue 템플릿에서 가장 먼저 만나는 문법 중 하나가 Mustache 출력입니다. 중괄호 두 쌍으로 감싼 표현식을 통해 스크립트에 있는 값을 화면에 보여줍니다. 이 문법은 단순해 보이지만 Vue의 선언적 렌더링을 이해하는 출발점입니다. 데이터가 바뀌면 템플릿에서 그 데이터를 사용하는 위치도 자동으로 갱신됩니다.

중요한 점은 Mustache 안에는 JavaScript 표현식을 넣을 수 있지만, 복잡한 로직을 길게 넣는 곳은 아니라는 점입니다. 예를 들어 간단한 문자열 결합이나 삼항 연산 정도는 가능하지만, 여러 줄의 조건문이나 배열 가공을 길게 넣으면 템플릿이 금방 지저분해집니다. 그런 로직은 computed나 함수로 빼는 편이 좋습니다.

또 하나 조심할 점은 HTML 출력입니다. 일반 Mustache 출력은 값을 텍스트로 다룹니다. 사용자가 입력한 문자열에 HTML 태그가 들어 있어도 태그로 실행하지 않고 문자로 보여주는 것이 기본적으로 안전합니다. 만약 HTML을 실제로 렌더링하고 싶다면 `v-html`을 써야 하지만, 보안 위험이 있어 신중해야 합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 이름, 학습 시간, 완료 여부를 화면에 출력합니다. 값이 바뀔 때 템플릿이 어떻게 따라 바뀌는지 확인해보세요.

{% raw %}
```vue
<script setup>
import { ref } from 'vue'

const name = ref('성규')
const studyMinutes = ref(30)
const finished = ref(false)
</script>

<template>
  <section>
    <h1>{{ name }}님의 Vue 학습</h1>
    <p>오늘 학습 시간: {{ studyMinutes }}분</p>
    <p>상태: {{ finished ? '완료' : '진행 중' }}</p>
  </section>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`name`, `studyMinutes`, `finished`는 스크립트에서 선언한 반응형 상태입니다. 템플릿은 이 값을 읽어서 문장을 만듭니다. `finished`처럼 boolean 값은 삼항 연산으로 간단히 표현할 수 있습니다. 다만 조건이 길어지면 템플릿에 직접 쓰지 말고 computed로 분리하는 것이 좋습니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: Mustache 안에 `if`, `for` 같은 문장을 직접 넣을 수는 없습니다. 표현식은 가능하지만 문장은 템플릿 지시문이나 computed로 분리해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 사용자 입력을 HTML로 렌더링하려고 `v-html`을 남용하면 XSS 위험이 생길 수 있습니다. 신뢰할 수 없는 문자열은 텍스트로 출력하는 것이 안전합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 템플릿에서 존재하지 않는 변수를 사용하면 원하는 값이 나오지 않습니다. 오타와 선언 위치를 먼저 확인해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

Mustache 문법은 간단한 출력에 매우 좋습니다. 하지만 템플릿이 계산식으로 가득 차면 화면 구조를 읽기 어려워집니다. "보여주는 일"은 템플릿에 두고, "계산하는 일"은 computed나 함수로 옮기는 기준을 세우면 유지보수가 쉬워집니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.

다음 글로 넘어가기 전에 예제 코드를 그대로 한 번 작성해보시고, 최소한 한 군데는 직접 바꿔보시는 것을 추천드립니다. 버튼 문구를 바꾸거나, 상태 초기값을 바꾸거나, 조건을 하나 추가하는 정도면 충분합니다. 그렇게 작은 변화를 직접 만들어보면 "아, 이 부분이 화면과 연결되어 있구나"라는 감각이 생깁니다.
