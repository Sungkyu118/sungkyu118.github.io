Flutter에서 화면 이동은 처음에는 `Navigator.push`만으로도 충분합니다. 하지만 앱 규모가 커지면 로그인 여부에 따라 접근을 막아야 하고, `/users/42`처럼 URL에 값을 넣어야 하고, 하단 탭 구조 안에서 화면을 유지해야 하는 요구가 생깁니다. 이때 모든 이동 로직을 위젯 곳곳에 흩뿌리면 나중에 라우트 이름 하나 바꾸는 일도 부담스러워집니다.

`go_router`는 Flutter 팀에서 권장하는 선언형 라우팅 패키지입니다. 경로를 한곳에 선언하고, 앱은 그 설정을 기준으로 화면을 이동합니다. 이번 글에서는 기본 설정부터 path parameter, query parameter, 로그인 redirect까지 순서대로 정리해보겠습니다.

## 설치

`pubspec.yaml`에 패키지를 추가합니다.

```yaml
dependencies:
  go_router: ^14.0.0
```

버전은 프로젝트의 Flutter SDK와 맞춰 확인하는 것이 좋습니다. 특히 오래된 Flutter 버전에서는 최신 `go_router`가 요구하는 SDK 조건을 만족하지 못할 수 있습니다. 팀 프로젝트라면 [FVM 글](/flutter/fvm)처럼 Flutter 버전을 고정해두면 이런 충돌을 줄일 수 있습니다.

## 가장 기본적인 라우터

`GoRouter`는 앱의 화면 목록을 선언합니다.

```dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

final router = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const HomePage(),
    ),
    GoRoute(
      path: '/settings',
      builder: (context, state) => const SettingsPage(),
    ),
  ],
);

class App extends StatelessWidget {
  const App({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      routerConfig: router,
    );
  }
}
```

`MaterialApp` 대신 `MaterialApp.router`를 사용한다는 점이 중요합니다. 기존 `home`, `routes`, `onGenerateRoute`를 섞어서 쓰면 라우팅 흐름을 이해하기 어려워질 수 있으니, go_router를 도입했다면 라우팅은 가능하면 한곳으로 모으는 편이 좋습니다.

## 화면 이동: go와 push의 차이

go_router에서 자주 쓰는 이동 메서드는 `go`와 `push`입니다.

```dart
context.go('/settings');
context.push('/settings');
```

`go`는 현재 위치를 지정한 경로로 바꿉니다. 로그인 후 홈으로 보내거나, 하단 탭을 전환하는 것처럼 "현재 화면 흐름을 교체"하는 느낌에 가깝습니다. `push`는 기존 화면 위에 새 화면을 쌓습니다. 상세 페이지로 들어갔다가 뒤로 가기로 목록에 돌아오는 흐름에 어울립니다.

```dart
ElevatedButton(
  onPressed: () => context.push('/products/10'),
  child: const Text('상품 상세 보기'),
)
```

잘못 사용하면 뒤로가기 동작이 이상해집니다. 예를 들어 로그인 성공 후 `push('/')`를 사용하면 뒤로가기 했을 때 로그인 화면으로 돌아갈 수 있습니다. 이 경우에는 `context.go('/')`가 더 자연스럽습니다.

## Path Parameter 사용하기

상세 화면은 보통 id가 필요합니다. `/users/:id` 형태로 path parameter를 선언할 수 있습니다.

```dart
GoRoute(
  path: '/users/:id',
  builder: (context, state) {
    final id = state.pathParameters['id']!;
    return UserDetailPage(userId: id);
  },
),
```

이동할 때는 실제 값을 넣습니다.

```dart
context.push('/users/42');
```

id가 숫자라면 화면 안에서 변환할 수 있습니다.

```dart
final rawId = state.pathParameters['id'];
final userId = int.tryParse(rawId ?? '');

if (userId == null) {
  return const InvalidUserPage();
}

return UserDetailPage(userId: userId);
```

`int.parse`를 바로 쓰면 잘못된 URL이 들어왔을 때 예외가 발생할 수 있습니다. 모바일 앱도 딥링크나 웹 빌드를 고려하면 외부에서 이상한 경로가 들어올 수 있으므로 안전하게 처리하는 습관이 좋습니다.

## Query Parameter 사용하기

검색어, 필터, 정렬 옵션처럼 없어도 화면을 만들 수 있는 값은 query parameter가 잘 어울립니다.

```dart
GoRoute(
  path: '/search',
  builder: (context, state) {
    final keyword = state.uri.queryParameters['q'] ?? '';
    final sort = state.uri.queryParameters['sort'] ?? 'recent';
    return SearchPage(keyword: keyword, sort: sort);
  },
),
```

이동할 때는 다음처럼 작성합니다.

```dart
context.go('/search?q=flutter&sort=recent');
```

문자열을 직접 이어 붙이면 공백이나 한글 검색어에서 문제가 생길 수 있으므로 `Uri`를 사용하는 방식이 더 안전합니다.

```dart
final uri = Uri(
  path: '/search',
  queryParameters: {
    'q': '플러터 라우팅',
    'sort': 'recent',
  },
);

context.go(uri.toString());
```

## redirect로 로그인 가드 만들기

로그인하지 않은 사용자가 마이페이지에 접근하면 로그인 화면으로 보내야 합니다. go_router에서는 `redirect`로 처리할 수 있습니다.

```dart
class AuthState extends ChangeNotifier {
  bool _isLoggedIn = false;

  bool get isLoggedIn => _isLoggedIn;

  void login() {
    _isLoggedIn = true;
    notifyListeners();
  }

  void logout() {
    _isLoggedIn = false;
    notifyListeners();
  }
}

final authState = AuthState();

final router = GoRouter(
  refreshListenable: authState,
  redirect: (context, state) {
    final loggedIn = authState.isLoggedIn;
    final goingToLogin = state.matchedLocation == '/login';

    if (!loggedIn && !goingToLogin) {
      return '/login';
    }

    if (loggedIn && goingToLogin) {
      return '/';
    }

    return null;
  },
  routes: [
    GoRoute(path: '/login', builder: (context, state) => const LoginPage()),
    GoRoute(path: '/', builder: (context, state) => const HomePage()),
    GoRoute(path: '/my', builder: (context, state) => const MyPage()),
  ],
);
```

`refreshListenable`을 넣으면 로그인 상태가 바뀔 때 redirect가 다시 평가됩니다. 이것이 없으면 로그인 상태는 바뀌었는데 라우터가 그 사실을 모르는 상황이 생길 수 있습니다.

## redirect에서 자주 나는 문제

첫 번째는 무한 redirect입니다. 로그인하지 않은 사용자를 `/login`으로 보내면서, `/login`에 있는 사용자도 다시 `/login`으로 보내면 같은 redirect가 반복됩니다. 그래서 위 코드처럼 `goingToLogin` 체크가 필요합니다.

두 번째는 redirect 안에서 화면 이동 함수를 직접 호출하는 실수입니다. redirect는 이동할 경로를 문자열로 반환하는 곳입니다. `context.go('/login')`을 호출하는 곳이 아닙니다.

```dart
// 잘못된 예
redirect: (context, state) {
  context.go('/login');
  return null;
}
```

세 번째는 인증 상태를 비동기로 직접 읽으려는 경우입니다. redirect는 동기적으로 판단하는 것이 기본이라, 토큰 저장소에서 매번 `await`로 토큰을 읽는 구조는 복잡해집니다. 보통 앱 시작 시 토큰을 읽어 인증 상태 객체에 반영하고, 라우터는 그 상태만 바라보게 만듭니다.

## 라우트 경로를 상수로 관리하기

경로 문자열을 화면마다 직접 쓰면 오타가 나기 쉽습니다.

```dart
class AppRoutes {
  static const home = '/';
  static const login = '/login';
  static const my = '/my';

  static String user(String id) => '/users/$id';
}
```

이렇게 두면 이동 코드가 더 읽기 좋아집니다.

```dart
context.push(AppRoutes.user('42'));
```

## 정리

`go_router`의 핵심은 라우팅 정보를 한곳에 선언하고, 화면에서는 의도에 맞게 `go` 또는 `push`로 이동하는 것입니다. 상세 화면에는 path parameter를, 검색과 필터에는 query parameter를 사용하면 URL 구조가 자연스러워집니다. 로그인 같은 접근 제어는 `redirect`와 상태 객체를 함께 사용하되, 무한 redirect와 비동기 상태 초기화를 조심해야 합니다. 하단 탭이 있는 앱이라면 이 기본 위에 `ShellRoute`를 추가하는 방식으로 확장하면 됩니다.
