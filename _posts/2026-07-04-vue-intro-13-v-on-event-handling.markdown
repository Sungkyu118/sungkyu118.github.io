# Vue 입문 13: v-on과 이벤트 처리의 기본 흐름

> 사용자 행동이 Vue 함수로 연결되고 상태 변경으로 이어지는 흐름을 익힙니다.

화면은 사용자가 보기만 하는 대상이 아닙니다. 버튼을 누르고, 입력창에 글을 쓰고, 폼을 제출하고, 목록 항목을 선택합니다. Vue에서는 이런 사용자 행동을 이벤트로 받아 함수와 연결합니다. 기본 문법은 `v-on`이고, 실제 코드에서는 축약형인 `@click`, `@input`, `@submit`을 더 자주 봅니다.

이벤트 처리를 배울 때 중요한 것은 "이벤트가 발생했다"에서 끝나지 않는 것입니다. 이벤트는 보통 상태 변경으로 이어집니다. 버튼 클릭은 숫자를 올리고, 입력 이벤트는 검색어를 바꾸고, 폼 제출은 API 호출을 시작합니다. Vue에서는 템플릿에서 이벤트를 선언하고, 스크립트에서 함수를 작성해 흐름을 나누는 것이 일반적입니다.

또 하나 알아둘 것은 이벤트 수식어입니다. 예를 들어 폼 제출은 브라우저의 기본 동작 때문에 페이지가 새로고침될 수 있습니다. Vue에서는 `@submit.prevent`처럼 수식어를 붙여 기본 동작을 막을 수 있습니다. 이렇게 하면 이벤트 객체를 직접 받아 `event.preventDefault()`를 호출하는 코드보다 템플릿 의도가 더 분명해집니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 입력창, 버튼, 폼 제출을 함께 보여줍니다. 각 이벤트가 어떤 함수를 호출하는지 따라가 보세요.

{% raw %}
```vue
<script setup>
import { ref } from 'vue'

const keyword = ref('')
const submittedKeyword = ref('')

function clearKeyword() {
  keyword.value = ''
}

function submitSearch() {
  submittedKeyword.value = keyword.value.trim()
}
</script>

<template>
  <form @submit.prevent="submitSearch">
    <input v-model="keyword" placeholder="검색어를 입력하세요" />
    <button type="submit">검색</button>
    <button type="button" @click="clearKeyword">지우기</button>
  </form>

  <p>입력 중: {{ keyword }}</p>
  <p>마지막 검색어: {{ submittedKeyword }}</p>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

입력창은 `v-model`로 `keyword`와 연결되어 있습니다. 검색 버튼은 폼 제출을 발생시키고, `@submit.prevent`가 새로고침을 막은 뒤 `submitSearch`를 실행합니다. 지우기 버튼은 `type="button"`으로 지정했기 때문에 폼 제출을 일으키지 않고 `clearKeyword`만 실행합니다. 이 작은 차이가 실제 폼 UI에서 매우 중요합니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 폼 안의 버튼은 기본적으로 submit 버튼처럼 동작할 수 있습니다. 단순 클릭 버튼이라면 `type="button"`을 명시하는 습관이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 템플릿에 `@click="doSomething"`을 썼는데 함수 이름이 다르면 클릭해도 동작하지 않습니다. 콘솔 경고와 오타를 확인해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 이벤트 처리 함수 안에서 너무 많은 일을 하면 테스트와 유지보수가 어려워집니다. 상태 변경, 검증, API 호출을 적절히 분리하는 것이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

간단한 클릭은 템플릿에 `@click="count++"`처럼 직접 쓸 수 있습니다. 하지만 동작이 조금이라도 길어지면 함수로 분리하는 편이 좋습니다. 템플릿은 사용자 행동과 함수 연결을 보여주고, 실제 로직은 스크립트에서 이름 있는 함수로 관리하는 방식이 읽기 쉽습니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.

Vue 입문 시리즈는 한 편씩 따로 읽어도 되지만, 가능하면 순서대로 따라가시는 것을 추천드립니다. 앞에서 만든 작은 감각이 뒤의 문법을 이해하는 발판이 되기 때문입니다. 지금 단계에서 중요한 것은 빠르게 많이 아는 것보다, 상태와 화면이 연결되는 흐름을 천천히 몸에 익히는 것입니다.
