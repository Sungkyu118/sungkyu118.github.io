# Vue 입문 21: Vue의 반응성은 정확히 무엇을 의미할까요?

Vue를 배우다 보면 반응성이라는 말을 아주 자주 듣습니다. 반응성은 단순히 "화면이 자동으로 바뀐다" 정도로만 이해해도 처음에는 괜찮지만, 조금 더 정확히 말하면 Vue가 상태가 읽히고 변경되는 관계를 추적한 뒤 필요한 화면 업데이트를 수행하는 성질입니다.

순수 JavaScript로 화면을 만들 때는 값이 바뀐 뒤 DOM도 직접 바꿔야 합니다. 예를 들어 숫자를 증가시키면 `textContent`를 다시 넣는 코드를 작성해야 합니다. Vue에서는 상태를 템플릿에서 사용하면 Vue가 그 연결을 알고 있다가 상태 변경 시 화면을 다시 렌더링합니다. 개발자는 "어떤 값을 바꿀지"에 집중하고, DOM 갱신의 세부 절차는 Vue에 맡깁니다.

하지만 반응성은 무조건 모든 JavaScript 변수를 추적한다는 뜻이 아닙니다. Vue가 추적할 수 있는 형태로 상태를 만들어야 합니다. Composition API에서는 `ref`와 `reactive`가 대표적인 도구입니다. 일반 변수는 값이 바뀌어도 Vue 화면 갱신 대상이 아닐 수 있습니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제에서 `normalCount`는 일반 변수이고, `reactiveCount`는 ref입니다. 템플릿에서 안정적으로 화면 갱신을 기대하려면 반응형 상태를 사용해야 합니다.

{% raw %}
```vue
<script setup>
import { ref } from 'vue'

let normalCount = 0
const reactiveCount = ref(0)

function increaseNormal() {
  normalCount += 1
  console.log('normalCount:', normalCount)
}

function increaseReactive() {
  reactiveCount.value += 1
}
</script>

<template>
  <section>
    <p>일반 변수: {{ normalCount }}</p>
    <p>반응형 상태: {{ reactiveCount }}</p>

    <button @click="increaseNormal">일반 변수 증가</button>
    <button @click="increaseReactive">반응형 상태 증가</button>
  </section>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`normalCount`는 콘솔에서는 증가하지만 Vue가 화면 갱신 대상으로 안정적으로 추적하는 상태가 아닙니다. 반면 `reactiveCount`는 `ref`로 만들어졌고 템플릿에서 사용되므로 값이 바뀌면 화면이 갱신됩니다. 템플릿에서는 ref가 자동으로 풀려 보이지만, 스크립트에서는 `.value`로 접근해야 한다는 점도 함께 기억해야 합니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 일반 변수를 바꿨는데 화면이 안 바뀐다면 Vue 반응형 상태로 만든 값인지 먼저 확인해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 스크립트에서 ref 값을 수정할 때 `.value`를 빼먹으면 원하는 값이 바뀌지 않습니다. 템플릿과 스크립트의 사용 방식이 다릅니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 반응성은 DOM 조작을 완전히 몰라도 된다는 뜻이 아닙니다. Vue가 언제 갱신하는지, nextTick이 왜 필요한지 같은 흐름은 점점 이해해야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

반응성은 Vue의 가장 큰 장점이지만, 모든 값을 반응형으로 만들 필요는 없습니다. 화면에 영향을 주지 않는 임시 계산값이나 함수 내부 지역 변수는 일반 변수로 충분합니다. 화면과 연결되어 바뀌어야 하는 값만 반응형 상태로 관리하는 것이 깔끔합니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
