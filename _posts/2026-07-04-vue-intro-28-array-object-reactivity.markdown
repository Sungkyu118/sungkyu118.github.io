Vue 3의 반응성은 강력하지만, 배열과 객체를 다룰 때 여전히 헷갈리는 상황이 생깁니다. 값을 바꿨다고 생각했는데 화면이 안 바뀌거나, 구조 분해한 값만 수정했더니 원본 상태가 바뀌지 않거나, reactive 객체를 통째로 교체했더니 연결이 이상해지는 경우입니다.

가장 먼저 확인할 것은 상태를 어떤 방식으로 만들었는지입니다. `ref([])`로 배열을 만들었다면 스크립트에서 배열 자체에 접근할 때 `items.value`가 필요합니다. `reactive({ ... })`로 객체를 만들었다면 속성 변경은 자연스럽지만, 객체 변수 자체를 새 객체로 바꾸는 방식은 조심해야 합니다.

또 하나의 원인은 구조 분해입니다. reactive 객체에서 속성만 꺼내 일반 변수처럼 쓰면 반응성 연결이 기대와 달라질 수 있습니다. 입문 단계에서는 구조 분해를 너무 빨리 쓰기보다, 먼저 `form.name`, `state.count`처럼 원본 객체를 통해 접근하는 습관을 들이는 것이 안전합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 배열 추가/삭제와 객체 속성 수정을 안전하게 처리하는 기본 형태입니다.

{% raw %}
```vue
<script setup>
import { reactive, ref } from 'vue'

const nextId = ref(3)
const items = ref([
  { id: 1, name: 'Vue 기초' },
  { id: 2, name: '반응성 연습' }
])

const form = reactive({
  name: ''
})

function addItem() {
  if (!form.name.trim()) return

  items.value.push({
    id: nextId.value,
    name: form.name.trim()
  })

  nextId.value += 1
  form.name = ''
}

function removeItem(id) {
  items.value = items.value.filter(item => item.id !== id)
}
</script>

<template>
  <input v-model="form.name" />
  <button @click="addItem">추가</button>

  <ul>
    <li v-for="item in items" :key="item.id">
      {{ item.name }}
      <button @click="removeItem(item.id)">삭제</button>
    </li>
  </ul>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`items`는 ref 배열이므로 스크립트에서 `items.value`로 접근합니다. 추가할 때는 `push`를 사용했고, 삭제할 때는 `filter`로 새 배열을 만들어 `items.value`에 다시 대입했습니다. `form`은 reactive 객체라 `form.name`처럼 속성을 직접 수정합니다. 각 항목은 안정적인 id를 key로 사용합니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: ref 배열을 스크립트에서 다룰 때 `.value`를 빼먹으면 실제 배열 메서드를 호출할 수 없습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: reactive 객체를 구조 분해한 뒤 분해된 변수만 수정하면 원본 상태와 연결이 기대와 다를 수 있습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 목록 렌더링 문제가 배열 반응성 문제처럼 보이더라도 실제 원인은 key 누락인 경우가 많습니다. 배열 수정과 key를 함께 확인하세요. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

배열과 객체 상태는 실제 서비스에서 가장 많이 쓰입니다. 그래서 처음에는 조금 장황해 보여도 명시적으로 다루는 편이 좋습니다. 상태가 어디에 있고, 어떤 함수가 수정하며, key가 무엇인지 드러나면 디버깅이 쉬워집니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
