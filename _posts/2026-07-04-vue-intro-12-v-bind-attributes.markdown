# Vue 입문 12: v-bind로 HTML 속성을 데이터와 연결하기

> HTML 속성도 고정 문자열이 아니라 Vue 상태에 따라 바뀔 수 있다는 감각을 잡습니다.

HTML을 작성할 때 `href`, `src`, `disabled`, `title`, `aria-label` 같은 속성은 보통 고정 문자열로 넣습니다. 하지만 실제 서비스에서는 속성이 데이터에 따라 달라지는 일이 많습니다. 로그인 상태에 따라 버튼을 비활성화하거나, API에서 받은 이미지 주소를 `src`에 넣거나, 선택된 탭에 따라 접근성 속성을 바꾸는 식입니다.

Vue에서는 `v-bind`를 사용해 HTML 속성을 JavaScript 값과 연결합니다. 축약 문법으로는 콜론을 많이 씁니다. 예를 들어 `v-bind:href="url"`은 `:href="url"`처럼 줄일 수 있습니다. 입문자는 처음에 콜론이 낯설지만, "오른쪽 값을 문자열 그대로 쓰지 말고 JavaScript 표현식으로 평가하라"는 표시라고 이해하면 됩니다.

속성 바인딩은 단순 편의 기능이 아닙니다. 화면 상태와 DOM 속성을 일관되게 유지하는 데 중요합니다. 버튼이 비활성 상태라면 CSS만 회색으로 만드는 것이 아니라 실제 `disabled` 속성도 함께 연결해야 사용자 경험과 접근성이 좋아집니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 링크 주소, 버튼 비활성 여부, title 속성을 Vue 상태와 연결합니다.

{% raw %}
```vue
<script setup>
import { ref } from 'vue'

const docsUrl = ref('https://vuejs.org/')
const isSaving = ref(false)
const buttonTitle = ref('저장 버튼입니다')
</script>

<template>
  <section>
    <a :href="docsUrl" target="_blank" rel="noreferrer">
      Vue 공식 문서 열기
    </a>

    <button :disabled="isSaving" :title="buttonTitle">
      {{ isSaving ? '저장 중...' : '저장하기' }}
    </button>
  </section>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`docsUrl`은 링크의 `href` 속성에 연결됩니다. `isSaving`이 true가 되면 버튼의 `disabled` 속성도 true가 됩니다. `buttonTitle`은 마우스를 올렸을 때 보이는 title 속성으로 들어갑니다. 템플릿에서 콜론이 붙은 속성은 고정 문자열이 아니라 스크립트의 값을 읽는다는 점이 핵심입니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 콜론을 빼면 오른쪽 값이 JavaScript 변수가 아니라 문자열 그대로 처리됩니다. `href="docsUrl"`과 `:href="docsUrl"`은 완전히 다릅니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: boolean 속성은 문자열 `"false"`를 넣는다고 false처럼 동작하지 않을 수 있습니다. 실제 boolean 값을 바인딩하는 것이 안전합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 외부 링크를 새 탭으로 열 때는 `rel="noreferrer"` 또는 보안 관련 속성을 함께 고려하는 것이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

속성 바인딩을 적극적으로 쓰면 UI 상태와 실제 DOM 속성을 맞추기 쉽습니다. 반대로 모든 값을 무조건 동적으로 만들면 템플릿이 복잡해집니다. 변하지 않는 값은 일반 속성으로 두고, 상태에 따라 바뀌는 값만 `v-bind`로 연결하는 기준이 좋습니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
