# Vue 입문 23: reactive로 객체 상태를 다룰 때의 장점과 주의점

> 여러 속성이 함께 움직이는 객체 상태를 reactive로 다루는 감각을 익힙니다.

`reactive`는 객체를 반응형으로 만들 때 자주 사용합니다. 로그인 폼, 검색 조건, 필터 상태처럼 여러 속성이 하나의 의미 있는 묶음으로 움직일 때 자연스럽습니다. 예를 들어 `email`, `password`, `rememberMe`를 각각 ref로 둘 수도 있지만, 로그인 폼이라는 하나의 객체로 묶으면 상태의 의미가 더 잘 드러날 수 있습니다.

`reactive`로 만든 객체는 속성에 직접 접근합니다. `form.email = '...'`처럼 쓸 수 있기 때문에 `ref`의 `.value`보다 직관적으로 느껴질 수 있습니다. 하지만 객체를 통째로 교체하거나 구조 분해할 때는 주의가 필요합니다. reactive는 프록시 객체를 통해 반응성을 제공하므로, 원본 연결을 끊어버리면 화면 갱신이 예상과 달라질 수 있습니다.

입문 단계에서는 reactive를 "속성이 여러 개인 상태 묶음"에 사용한다고 생각하면 좋습니다. 다만 무조건 reactive만 쓰기보다 ref와의 차이를 이해하면서 선택해야 합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 회원 정보 폼을 reactive 객체로 관리합니다. 각 입력은 객체의 속성과 v-model로 연결됩니다.

{% raw %}
```vue
<script setup>
import { reactive } from 'vue'

const form = reactive({
  name: '',
  email: '',
  receiveNews: false
})

function resetForm() {
  form.name = ''
  form.email = ''
  form.receiveNews = false
}
</script>

<template>
  <label>
    이름
    <input v-model="form.name" />
  </label>

  <label>
    이메일
    <input v-model="form.email" />
  </label>

  <label>
    <input v-model="form.receiveNews" type="checkbox" />
    뉴스레터 받기
  </label>

  <button @click="resetForm">초기화</button>

  <pre>{{ form }}</pre>
</template>
```
{% endraw %}

## 코드가 움직이는 순서

`form`은 reactive 객체입니다. 템플릿에서는 `form.name`, `form.email`처럼 속성에 접근합니다. 초기화 함수에서는 `form = ...`처럼 객체 자체를 새로 대입하지 않고, 기존 reactive 객체의 속성을 하나씩 바꿉니다. 이렇게 하면 Vue가 추적하던 반응형 연결이 유지됩니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: reactive 객체를 통째로 새 객체로 바꾸는 방식은 피하는 것이 좋습니다. 기존 객체의 속성을 수정하는 방식이 안전합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: reactive 객체를 구조 분해하면 반응성 연결이 약해질 수 있습니다. 구조 분해가 필요하면 `toRefs` 같은 도구를 나중에 함께 배워야 합니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 객체가 너무 깊고 복잡하면 어디서 상태가 바뀌는지 추적하기 어려워집니다. 큰 상태는 역할별로 나누는 것이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

reactive는 객체 폼 상태처럼 묶음의 의미가 분명할 때 좋습니다. 반면 단일 boolean, 숫자, 문자열 상태는 ref가 더 단순합니다. 팀마다 선호가 다를 수 있으므로 중요한 것은 일관성입니다. 같은 프로젝트 안에서 기준 없이 섞으면 읽는 사람이 힘들어집니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.
