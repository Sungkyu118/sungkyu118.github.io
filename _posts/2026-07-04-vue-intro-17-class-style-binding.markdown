# Vue 입문 17: 조건부 클래스와 스타일 바인딩을 실무처럼 사용하기

사용자 화면은 상태에 따라 모양이 바뀝니다. 선택된 탭은 강조되어야 하고, 오류가 있는 입력창은 빨간 테두리가 필요하며, 저장 중인 버튼은 비활성처럼 보여야 합니다. Vue에서는 `:class`와 `:style`을 사용해 이런 시각적 상태를 데이터와 연결할 수 있습니다.

클래스 바인딩은 보통 상태 이름과 CSS 클래스를 연결할 때 좋습니다. 예를 들어 `{ active: isActive, error: hasError }`처럼 쓰면 상태가 true일 때만 해당 클래스가 붙습니다. 스타일 바인딩은 계산된 크기, 색상, 위치처럼 값 자체가 동적으로 바뀌어야 할 때 사용할 수 있습니다.

실무에서는 가능하면 클래스 중심으로 스타일을 관리하는 편이 좋습니다. 인라인 스타일은 빠르게 적용하기에는 좋지만, 디자인 규칙이 여러 곳에 흩어질 수 있습니다. 색상, 간격, 상태 표현은 CSS 클래스에 두고, 정말 값이 동적으로 계산될 때만 `:style`을 쓰는 식으로 기준을 잡으면 유지보수가 편합니다.

## 이번 글에서 먼저 잡을 관점

이번 주제에서 가장 중요한 것은 문법을 외우는 것보다 흐름을 이해하는 것입니다. Vue 코드는 보통 상태를 준비한다 -> 템플릿에서 상태를 읽는다 -> 사용자 행동으로 상태가 바뀐다 -> Vue가 화면을 다시 맞춘다는 순서로 움직입니다. 이 순서를 머릿속에 두고 읽으면 새로운 문법을 만나도 훨씬 덜 흔들립니다.

또 하나 중요한 점은 Vue가 HTML, CSS, JavaScript를 대체하는 것이 아니라는 사실입니다. Vue는 이 세 가지를 더 구조적으로 연결해주는 도구입니다. 그래서 예제를 따라 칠 때도 "이 문법이 Vue에서만 특별한가?", "아니면 원래 HTML/JavaScript 개념을 Vue 방식으로 연결한 것인가?"를 나누어 생각하면 좋습니다.

처음에는 한 번에 완벽하게 이해하지 못해도 괜찮습니다. 대신 예제 코드를 조금씩 바꿔보면서 어떤 값이 바뀌면 화면의 어느 부분이 바뀌는지 확인해보세요. 손으로 바꿔본 경험이 쌓이면, 단순히 읽기만 했을 때보다 훨씬 빠르게 감이 잡힙니다.

## 작은 실습으로 확인해보기

아래 예제는 입력값이 비어 있을 때 오류 클래스를 붙이고, 진행률 값을 인라인 스타일로 연결합니다.

```vue
<script setup>
import { computed, ref } from 'vue'

const title = ref('')
const progress = ref(40)

const hasError = computed(() => title.value.trim().length === 0)
</script>

<template>
  <section>
    <label>
      제목
      <input v-model="title" :class="{ error: hasError }" />
    </label>
    <p v-if="hasError" class="message">제목을 입력해주세요.</p>

    <div class="progress">
      <div class="bar" :style="{ width: progress + '%' }"></div>
    </div>
  </section>
</template>

<style scoped>
.error {
  border: 2px solid #ef4444;
}

.message {
  color: #ef4444;
}

.progress {
  height: 10px;
  background: #e5e7eb;
}

.bar {
  height: 100%;
  background: #42b883;
}
</style>
```

## 코드가 움직이는 순서

`hasError`는 제목이 비었는지 계산하는 computed입니다. 입력창의 `:class`는 `hasError`가 true일 때 `error` 클래스를 붙입니다. 진행률 막대는 `progress` 숫자에 따라 width 값이 달라져야 하므로 `:style`로 연결했습니다. 클래스와 스타일의 역할을 나누어 쓰는 것이 핵심입니다.

여기서 꼭 기억하셔야 할 부분은 Vue가 화면을 갱신해준다고 해서 개발자가 흐름을 몰라도 되는 것은 아니라는 점입니다. 오히려 Vue를 잘 쓰려면 상태가 어디에 있고, 어떤 이벤트나 함수가 그 상태를 바꾸며, 템플릿이 그 상태를 어떻게 읽는지 계속 추적할 수 있어야 합니다. 작은 예제부터 이 흐름을 말로 설명해보면 나중에 코드가 길어져도 훨씬 덜 막힙니다.

## 자주 만나는 에러와 유의사항

- **확인 포인트**: 조건부 클래스 이름을 너무 추상적으로 지으면 나중에 의미를 알기 어렵습니다. `red`, `big`보다 `error`, `selected`, `disabled`처럼 상태를 드러내는 이름이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: 인라인 스타일을 남용하면 CSS에서 전체 디자인을 조정하기 어려워집니다. 반복되는 시각 규칙은 클래스에 두세요. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.
- **확인 포인트**: computed 없이 템플릿 안에서 조건식을 계속 반복하면 수정할 때 빠뜨리기 쉽습니다. 여러 곳에서 쓰는 조건은 computed로 빼는 것이 좋습니다. 이 문제는 처음에는 작은 실수처럼 보이지만, 화면이 커질수록 원인을 찾기 어려워질 수 있습니다. 그래서 코드를 작성할 때마다 상태가 어디에서 만들어지고, 어디에서 바뀌며, 템플릿에서는 어떤 이름으로 읽히는지 함께 확인하는 습관이 좋습니다.

에러를 만났을 때는 먼저 터미널 로그와 브라우저 개발자 도구 Console을 함께 봐야 합니다. Vue 프로젝트는 빌드 단계에서 나는 오류와 브라우저 실행 중에 나는 오류가 다를 수 있습니다. 터미널은 정상처럼 보여도 브라우저 콘솔에는 컴포넌트 렌더링 오류가 남아 있을 수 있고, 반대로 브라우저를 열기도 전에 Vite 개발 서버가 실패하는 경우도 있습니다.

## 실무에서 생각할 점

클래스 바인딩은 디자인 시스템과 잘 어울리고, 스타일 바인딩은 동적인 수치 표현에 강합니다. 둘 중 하나만 고집하기보다 "상태 이름을 표현하는가, 실제 값을 계산하는가"를 기준으로 선택하면 실무에서도 코드가 깔끔해집니다.

실무에서는 "동작한다"만으로는 부족한 경우가 많습니다. 다른 사람이 읽었을 때 의도를 이해할 수 있는지, 요구사항이 조금 바뀌어도 고치기 쉬운지, 에러 상황에서도 사용자가 무엇을 해야 하는지 알 수 있는지가 중요합니다. 입문 시리즈에서 계속 예제와 주의사항을 함께 보는 이유도 여기에 있습니다. 문법을 하나 배울 때마다 그 문법이 실패할 수 있는 지점까지 같이 봐야 실제 프로젝트에서 덜 흔들립니다.

다음 글로 넘어가기 전에 예제 코드를 그대로 한 번 작성해보시고, 최소한 한 군데는 직접 바꿔보시는 것을 추천드립니다. 버튼 문구를 바꾸거나, 상태 초기값을 바꾸거나, 조건을 하나 추가하는 정도면 충분합니다. 그렇게 작은 변화를 직접 만들어보면 "아, 이 부분이 화면과 연결되어 있구나"라는 감각이 생깁니다.
