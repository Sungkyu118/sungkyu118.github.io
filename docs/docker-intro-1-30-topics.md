# Docker 입문 1~30 주제 정의

## 문서 목적

이 문서는 `Docker / Kubernetes / Cloud Native` 시리즈 중에서 가장 먼저 진행할 `Docker 입문 1~30` 포스트의 세부 주제를 정의하기 위한 문서입니다. 이전에 작성한 전체 기획 문서가 시리즈의 큰 방향을 잡는 문서였다면, 이번 문서는 실제 글을 쓰기 위한 바로 직전 단계의 작업 문서에 가깝습니다.

이 문서의 핵심 목표는 두 가지입니다.

첫 번째는 글 순서를 자연스럽게 만드는 것입니다. Docker는 처음 접하는 분들에게는 명령어가 많아 보이고, 이미지, 컨테이너, 볼륨, 네트워크, 레이어, Dockerfile, Compose 같은 개념이 한꺼번에 쏟아지는 주제입니다. 그래서 순서를 잘못 잡으면 독자가 금방 지치거나, 아직 배우지 않은 개념을 먼저 만나 혼란을 느끼기 쉽습니다.

두 번째는 각 포스트가 너무 넓지도 않고 너무 얕지도 않게 분리되도록 만드는 것입니다. 예를 들어 `Dockerfile 완전 정복`처럼 한 글에 너무 많은 내용을 담으려 하면 설명이 흐려지고, 반대로 `docker ps 명령어 소개`처럼 너무 잘게 쪼개면 시리즈 전체 흐름이 끊어질 수 있습니다. 따라서 이번 문서에서는 각 글이 하나의 핵심 질문을 중심으로 움직이도록 설계합니다.

---

## 전체 구성 원칙

`Docker 입문 1~30`은 아래 6개 구간으로 나눕니다.

1. `입문 개념 구간`
2. `이미지와 컨테이너 구간`
3. `Dockerfile 구간`
4. `저장소, 볼륨, 네트워크 구간`
5. `Docker Compose 구간`
6. `실전 연결 구간`

이렇게 나누는 이유는 Docker를 배우는 실제 학습 흐름과 비슷하기 때문입니다. 대부분의 입문자는 먼저 "Docker가 왜 필요한지"를 이해해야 하고, 그 다음에는 "이미지와 컨테이너가 무엇인지"를 알아야 하며, 그 다음에는 "내 애플리케이션을 어떻게 이미지로 만들지"를 궁금해합니다. 그 이후에야 볼륨, 네트워크, Compose 같은 운영성 개념이 자연스럽게 이어집니다.

## 시리즈에서 반드시 유지할 설명 방식

각 주제는 단순 제목 나열이 아니라, 실제 글로 확장할 때 아래 요소를 포함할 수 있어야 합니다.

- 왜 이 개념이 필요한지
- 어떤 상황에서 처음 마주치는지
- 초보자가 가장 자주 헷갈리는 포인트가 무엇인지
- 기본 예제는 어떻게 보여줄지
- 잘못된 예제와 올바른 예제를 어떻게 비교할지
- 실무에서 어떤 식으로 연결되는지

특히 Docker 주제는 명령어 실행 결과만 보여주면 이해가 깊어지지 않기 쉽습니다. 그래서 각 글은 가능하면 "문제 상황 -> Docker 개념 소개 -> 예제 -> 흔한 실수 -> 개선 방식 -> 실무 연결" 순서로 쓰는 것을 기본 방향으로 잡습니다.

## 1구간: 입문 개념 구간

이 구간의 목표는 Docker를 처음 접하는 분들이 가장 큰 그림을 이해하도록 돕는 것입니다. 아직은 명령어를 많이 외우게 하기보다, Docker가 왜 등장했고 어떤 문제를 해결하려고 하는지에 집중하는 편이 좋습니다.

### 1. Docker는 왜 필요할까요?

- 핵심 질문: "내 컴퓨터에서는 되는데 서버에서는 안 되는 문제를 Docker가 어떻게 줄여줄까요?"
- 꼭 다룰 내용:
  - 개발 환경 차이 문제
  - 실행 환경 재현성
  - 의존성 충돌
  - 배포 단위 표준화
- 추천 예시:
  - 로컬에서는 잘 되는데 서버에서 Java 버전이 달라 실패하는 상황

### 2. 컨테이너와 가상머신은 무엇이 다를까요?

- 핵심 질문: "Docker 컨테이너는 VM보다 가볍다고 하는데, 정확히 뭐가 다른 걸까요?"
- 꼭 다룰 내용:
  - 하이퍼바이저와 OS 공유 개념
  - 시작 속도, 자원 사용, 격리 수준 차이
  - 언제 VM이 더 적합한지

### 3. 이미지와 컨테이너는 왜 다른 개념일까요?

- 핵심 질문: "이미지는 파일 같고, 컨테이너는 실행 중인 인스턴스라고 하는데 이 차이가 왜 중요한가요?"
- 꼭 다룰 내용:
  - 이미지 = 설계도, 컨테이너 = 실행 결과
  - 하나의 이미지로 여러 컨테이너 실행 가능
  - 삭제와 재생성 개념

### 4. Docker 설치 후 가장 먼저 확인해야 할 것들

- 핵심 질문: "Docker를 설치한 뒤 무엇부터 점검해야 할까요?"
- 꼭 다룰 내용:
  - `docker --version`
  - `docker info`
  - 데몬 실행 여부
  - 권한 문제와 Windows/Mac 차이

### 5. 처음 실행하는 hello-world는 무엇을 보여줄까요?

- 핵심 질문: "`docker run hello-world`는 단순한 예제 같지만 왜 입문에서 중요한가요?"
- 꼭 다룰 내용:
  - 이미지 pull
  - 컨테이너 생성
  - 실행 후 종료
  - 로그 확인 흐름

## 2구간: 이미지와 컨테이너 구간

이 구간은 Docker를 "실행해보는 단계"에 해당합니다. 입문자분들이 가장 흥미를 느끼는 구간이기도 하지만, 동시에 상태 변화와 생명주기 개념을 놓치기 쉬운 구간이기도 합니다.

### 6. docker run 명령은 실제로 어떤 일을 한 번에 할까요?

- 핵심 질문: "`docker run` 한 줄에 왜 이렇게 많은 기능이 들어 있을까요?"
- 꼭 다룰 내용:
  - 이미지 확인
  - pull
  - create
  - start
  - attach

### 7. 실행 중인 컨테이너와 종료된 컨테이너를 어떻게 구분할까요?

- 핵심 질문: "`docker ps`와 `docker ps -a`는 언제 각각 봐야 할까요?"
- 꼭 다룰 내용:
  - 실행 상태 확인
  - 종료 원인 추적 시작점
  - 이름과 ID 보는 법

### 8. 컨테이너 로그는 어떻게 읽어야 할까요?

- 핵심 질문: "컨테이너가 바로 종료되거나 이상하게 동작할 때 무엇부터 봐야 할까요?"
- 꼭 다룰 내용:
  - `docker logs`
  - 로그 tail
  - 애플리케이션 에러와 컨테이너 에러 구분

### 9. 컨테이너 안으로 들어간다는 것은 무슨 의미일까요?

- 핵심 질문: "`docker exec -it`는 왜 자주 쓰이고, 언제는 오히려 남용하면 안 될까요?"
- 꼭 다룰 내용:
  - 셸 접속
  - 디버깅 용도
  - 임시 변경은 왜 휘발되는지

### 10. 컨테이너를 중지, 시작, 재시작, 삭제하는 흐름 이해하기

- 핵심 질문: "컨테이너를 지운다는 것이 실제로 무엇을 잃는다는 뜻일까요?"
- 꼭 다룰 내용:
  - `stop`, `start`, `restart`, `rm`
  - 상태와 데이터 분리 필요성

### 11. 이름, ID, 태그는 어떻게 읽는 것이 좋을까요?

- 핵심 질문: "컨테이너 이름과 이미지 태그를 대충 써도 괜찮을까요?"
- 꼭 다룰 내용:
  - 이름 관리
  - 태그 전략
  - `latest` 태그의 함정

## 3구간: Dockerfile 구간

이 구간부터는 단순 실행을 넘어서 "내 애플리케이션을 Docker 이미지로 패키징하는 방법"을 다루게 됩니다. 입문자에게는 여기서부터 갑자기 어려워질 수 있으므로, 각 명령어의 의미를 매우 자세히 설명해야 합니다.

### 12. Dockerfile은 왜 필요할까요?

- 핵심 질문: "`docker run`으로 충분한 것 같은데 왜 Dockerfile까지 써야 하나요?"
- 꼭 다룰 내용:
  - 수동 실행의 한계
  - 재현 가능한 빌드
  - 팀 공유 가능성

### 13. Dockerfile의 기본 구조를 처음 읽는 방법

- 핵심 질문: "`FROM`, `WORKDIR`, `COPY`, `RUN`, `CMD`는 각각 어떤 역할을 하나요?"
- 꼭 다룰 내용:
  - 가장 기본적인 명령어 흐름
  - 파일 복사와 실행 명령 차이

### 14. FROM은 왜 모든 Dockerfile의 출발점일까요?

- 핵심 질문: "베이스 이미지를 고르는 기준은 무엇일까요?"
- 꼭 다룰 내용:
  - 운영체제 계열
  - 언어 런타임 포함 여부
  - slim/alpine 태그 차이

### 15. COPY와 ADD는 무엇이 다를까요?

- 핵심 질문: "둘 다 복사 명령처럼 보이는데 왜 나눠져 있을까요?"
- 꼭 다룰 내용:
  - 일반적인 권장 방식
  - 압축 자동 해제와 URL 기능
  - 왜 보통은 `COPY`를 더 권장하는지

### 16. RUN, CMD, ENTRYPOINT는 언제 각각 써야 할까요?

- 핵심 질문: "이 세 명령어가 전부 실행과 관련 있어 보여서 헷갈리는데, 정확히 어떻게 다른가요?"
- 꼭 다룰 내용:
  - 빌드 시점과 실행 시점 차이
  - 기본 실행 명령
  - 인자 override

### 17. Docker 이미지 빌드는 어떤 순서로 진행될까요?

- 핵심 질문: "`docker build`를 할 때 내부에서는 무슨 일이 벌어질까요?"
- 꼭 다룰 내용:
  - 빌드 컨텍스트
  - 레이어
  - 캐시
  - `.dockerignore`

### 18. 이미지 레이어와 캐시는 왜 빌드 속도에 큰 영향을 줄까요?

- 핵심 질문: "Dockerfile 순서 하나로 빌드 시간이 달라지는 이유는 무엇인가요?"
- 꼭 다룰 내용:
  - 변경이 자주 일어나는 파일 배치
  - 의존성 설치 캐시
  - 레이어 재사용

### 19. .dockerignore는 왜 생각보다 중요할까요?

- 핵심 질문: "작은 설정 파일 하나가 빌드 속도와 보안에 왜 영향을 줄까요?"
- 꼭 다룰 내용:
  - 불필요한 파일 전송
  - `node_modules`, `.git`, 로그 파일
  - 민감정보 노출 위험

### 20. 내 애플리케이션을 첫 Docker 이미지로 만들어보기

- 핵심 질문: "이론을 배웠다면 이제 실제 애플리케이션을 어떻게 이미지로 만들까요?"
- 꼭 다룰 내용:
  - 간단한 예제 앱
  - Dockerfile 작성
  - `docker build`
  - `docker run`

## 6구간: 실전 연결 구간

마지막 구간은 단순 입문 마무리가 아니라, 다음 시리즈와 기존 블로그 자산을 연결하는 역할을 합니다. 즉, Docker를 배운 독자가 "이제 실제 프로젝트에 어떻게 붙이지?"라는 질문을 하게 되는 지점에 답해줘야 합니다.

### 30. 범용 샘플 애플리케이션을 Docker로 감싸는 첫 실전 예제

- 핵심 질문: "지금까지 배운 내용을 특정 프레임워크에 의존하지 않고 실제 애플리케이션 실행 흐름에 어떻게 적용할까요?"
- 꼭 다룰 내용:
  - 간단한 범용 앱 또는 정적 웹 예제
  - 기본 Dockerfile
  - 포트 설정
  - 환경 변수
  - 이후 Compose, Redis, Kubernetes 글로 이어지는 연결

이 마지막 글은 단순 실습 글로 끝내지 않고, 다음 단계 안내 역할도 같이 해야 합니다. 예를 들어 "이제 단일 컨테이너를 넘어서 앱과 DB, 캐시를 함께 관리하려면 Compose가 중요해지고, 더 큰 규모 운영에서는 Kubernetes가 필요해진다"는 흐름을 자연스럽게 연결해야 합니다. 여기서는 특정 백엔드 프레임워크를 전제로 하기보다, 누구나 따라 할 수 있는 범용 샘플을 사용하는 편이 시리즈 전체의 접근성을 더 높여줍니다.

## 이 30개 주제가 좋은 이유

이번 30개 주제는 단순히 Docker 기능 목록을 번호만 붙여 나열한 것이 아닙니다. 입문자가 실제로 이해하는 순서를 기준으로 재배열한 목록입니다.

- 1~5는 왜 Docker를 배워야 하는지와 가장 기본적인 개념을 다집니다.
- 6~11은 컨테이너 실행과 상태 변화를 익히게 만듭니다.
- 12~20은 Dockerfile과 이미지 빌드를 통해 "내 애플리케이션 패키징"으로 들어갑니다.
- 21~25는 데이터, 포트, 네트워크, 환경 변수처럼 운영에 가까운 요소를 다룹니다.
- 26~29는 실제 개발 환경 구성에 가장 많이 쓰이는 Compose 흐름을 다룹니다.
- 30은 특정 프레임워크에 묶이지 않는 첫 실전 적용 글입니다.

즉, 이 목록은 입문에서 실전 직전 단계까지 도달하게 만드는 최소한의 첫 번째 완성 단위라고 볼 수 있습니다.
